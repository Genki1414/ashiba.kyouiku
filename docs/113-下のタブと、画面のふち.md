# 113　下のタブと、画面のふち

2026-09-10。げんきさん
「下記タブが小さくてiPhoneのバーと被って変な挙動するから少し修正して」。

## 何が起きていたか

ホーム画面のアプリで開くと、iPhone の**下の横棒**（ホームインジケータ）が
札の字にちょうど重なっていた。押したつもりが、ホームに戻ってしまう。

余白は取ってあった。

```
paddingBottom: env(safe-area-inset-bottom)
```

ところがこれは **0 になっていた。**`viewport-fit=cover` を宣言していないと、
iOS は `env(safe-area-inset-*)` を全部 0 として返す。
書いてあるのに効いていない、いちばん見つけにくい形だった。

## 直したこと

### ① 画面のふちまで使うと宣言した

`src/app/layout.tsx` の viewport に `viewportFit: "cover"`。
これで `env(safe-area-inset-bottom)` が本物の値（横棒のぶん、34px ほど）を返す。

### ② 上のぶんも取り返した

ふちまで使うと、**上も時計や電池の下に潜る。**
`globals.css` の body に `padding-top: env(safe-area-inset-top)`。
ブラウザで開いたときは 0 なので、見た目は変わらない。

**この2つは組で持つ。**片方だけだと、必ずどちらかの端が潜る。

### ③ 押す所を大きくした

| | 前 | いま |
| --- | --- | --- |
| 札1つの高さ | 46px | **52px** |
| 絵の大きさ | 15px | 20px |
| 字の大きさ | 10.5px | 11.5px |

指で押す所は 44px 以上ないと、隣を押してしまう。手袋のままなら、なおさら。

### ④ 空ける分を1か所で決めた

```ts
const ROW = 52;
const GAP = "max(env(safe-area-inset-bottom), 10px)";
```

`max` にしてあるので、`env` が 0 の相手（ブラウザ・Android の一部）でも
指1本ぶんは必ず空く。

上に作る隙間（spacer）も**同じ式で出す。**
別々に書くと、片方を直したときに、いちばん下の行が札の下に隠れる。
前は `h-[62px]` と決め打ちで、横棒のぶんが入っていなかった。

## 確かめ方

`tests/nav-check.mjs` が、4画面で測る。

```
/        position:fixed  下まで送ったあと 下端844/画面844  固定OK
         押す所 98×52px OK ／ 下に空けた分 10px OK ／ 隙間 63px と札 63px OK
```

手元の Chromium は `env` が 0 なので、ここで見えるのは**逃げ道のほう**
（0 でも必ず空くか）。iPhone の実機では、ここに横棒のぶんが入る。

見張り（api-shape）は、cover と上の余白が**両方あるか**を見る。
片方を消したら止まる。
