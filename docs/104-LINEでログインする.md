## なぜ

現場の職人は、メールを持っていない・使っていない人が多い。メールとパスワードで
入る形は、そこで止まる。忘れたときの決め直しも、メールが読めないと詰む。

## つなぎ方

Supabase のログインに LINE は入っていない。だから橋を自分で架ける。

1. `/api/line/login` … state と nonce を作ってクッキーに残し、LINE の認可画面へ送る
2. LINE で本人が許可 → `/auth/line` に戻る
3. state を確かめる（**よそから差し込まれていないか**）
4. code を LINE のトークンの口に渡し、返ってきた `id_token` を **LINE の verify に
   確かめてもらう**（自分で開いて読まない。偽物を見抜けない）
5. `users.line_user_id` でその人を探す。無ければ利用者を作って結ぶ
6. `generateLink`（magiclink）で1回きりの合図を作り、`verifyOtp` でクッキーの
   ログインに引き換える。**メールは送らない**

## 決めたこと

- **1つの LINE 番号は1人にだけ**（`users_line_user_id_key`）。結び直しが起きると、
  よその人の受講記録に入れてしまう
- **本人には紐付けを触らせない**（0003 の guard に足した）。触れると、まだ誰も
  使っていない番号を自分に付けて、あとからその番号で来た人を乗っ取れる
- **LINE の表示名は修了証に使わない。**本名とは限らない。氏名はマイページで入れる
- メールを持っていない人には `line-<番号>@line.invalid` という**届かない住所**を作る。
  間違って送っても、誰にも届かない
- LINE がメールを返したときは、同じメールの利用者に結ぶ（メールで登録済みの人が
  あとから LINE で来ても、1人のまま）
- `scope` は `openid profile` だけ。email は LINE の審査が要るうえ、持っていない人が多い
- `bot_prompt=aggressive` で友だち追加も勧める（リッチメニューを使ってもらうため）

## げんきさんの作業（LINE Developers）

1. LINE Developers で**プロバイダー**を作る（店ごと：足場屋革命／特別教育ドットコム）
2. **LINE ログイン**チャネルを作る
   - コールバックURL：`https://（店の住所）/auth/line`
   - 例：`https://www.tokubetsu-kyouiku.com/auth/line`
   - 「リンクされたLINE公式アカウント」に、その店の公式アカウントを指定する
3. Vercel の環境変数（Production）に入れる
   - `LINE_LOGIN_CHANNEL_ID`（Config）
   - `LINE_LOGIN_CHANNEL_SECRET`（**Secret**。NEXT_PUBLIC_ を付けない）
4. Redeploy する
5. `/setup` の「LINEログイン」が緑になれば、ログイン画面に「LINEではじめる」が出る

**チャネルは店ごとに分ける。**同じチャネルを使い回すと、特別教育ドットコムで
入った人が足場屋革命の公式アカウントの友だちになる。
