# ログイン（Supabase Auth）

受講の記録を**本人のもの**として残すために入れました。
いまはこれが、URLが外から開かれないための守りも兼ねています。

## 決まり

| 状態 | どうなるか |
|---|---|
| Supabase を設定していない | **ログインを求めない。** 記録は端末内だけ |
| Supabase を設定している | **ログインしないと何も開けない。** 記録は本人の受講に残る |

設定していないのにログインを求めても、記録の残し先が無いので意味がありません。
手元で画面を確かめるときは、そのまま使えます。

ログイン前でも開ける道は `src/lib/authGate.ts` にまとめてあります
（ログイン画面・メールの確認リンクの戻り先・圏外の1枚・`/api/health`・部品）。
**ここを間違えると、ログイン画面が開けないか、逆に中身が素通しになります。**
`npm run test:authgate` が見張っています。

## Supabase 側でやること（げんきさんの作業）

### 1. SQL を流し直す

`supabase/apply-all.sql` を SQL Editor にもう一度貼って **Run**。
何度実行しても壊れない書き方なので、そのまま上書きで構いません。

`0004_auth.sql` が増えています。中身は、

- **auth.users に行ができたら public.users を作る**引き金
  （登録のときに入れてもらった氏名が入ります）
- すでにいて `public.users` が無い人の後追い
- 受講（enrollments）を1人1件だけにする索引

### 2. メールでの登録を有効にする

**Authentication → Providers → Email** を開いて、

| 項目 | どうするか |
|---|---|
| Enable Email provider | **ON** |
| Confirm email | 好きな方。**OFF なら登録してすぐ入れます** |

`Confirm email` を ON にすると、登録のあとメールのリンクを押すまで入れません。
Supabase の標準のメール送信は**1時間に数通まで**なので、
確かめている間は OFF、人に配るときに ON、が楽です。

**Authentication → URL Configuration** に、次の3つを入れてください。
（`Confirm email` が OFF でも、**合言葉の決め直しに要ります**）

- **Site URL** … `https://kyouiku.ashibase.jp`
- **Redirect URLs**
  - `https://kyouiku.ashibase.jp/auth/confirm` … 登録の確認
  - `https://kyouiku.ashibase.jp/auth/reset` … **合言葉の決め直し**

### 合言葉の決め直し

ログインの画面の「合言葉を忘れた」から送ります。

戻り先の住所は**決め打ち**にしてあります（`src/lib/siteUrl.ts` の
`FALLBACK_SITE`）。Vercel は配信のたびに違う住所も配るので、
いま開いている住所を使うと、上の Redirect URLs と合わずに弾かれるためです。
手元（localhost）で動かしているときだけは、手元へ戻します。

**独自ドメインにしたら、`FALLBACK_SITE` と Redirect URLs の両方を変えます。**

道を2つに分けてあるのは、いまの作り（PKCE）のリンクには `code` しか
付いてこないからです。中身を見ても「決め直しかどうか」が分からず、
分からないまま中へ通すと、決め直さないまま入ってしまい、
次に閉じたときにまた入れなくなります。

| 道 | いつ来るか | どこへ送るか |
|---|---|---|
| `/auth/confirm` | 登録の確認 | ホーム |
| `/auth/reset` | 合言葉の決め直し | `/login/new`（新しい合言葉を入れる画面） |

> 決め直しのメールは、**登録の無いアドレスでも「送りました」と出します**。
> 出し分けると、誰が登録しているかを外から当てられるためです。

> 唯一の教育担当者が忘れても、ここから自分で戻せます。
> それでも入れないときは、本部が `/owner` の「事業者と記録」から
> 教育担当者を立て直せます。

### 3. Vercel の環境変数

いままでどおり `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` が要ります。
**`NEXT_PUBLIC_*` は組み立てのときに埋め込まれる**ので、
変えたら必ず **Redeploy（ビルドの写しを使わない）** をしてください。

`DEV_ENROLLMENT_ID` は**消して構いません**。
これはログインが無かったころの逃げ道で、
本番に残すとログインしていない人の記録が1か所に混ざります。

## 誰として記録しているか

`/setup` と `/api/health` の `auth` で見られます。

```json
"auth": { "required": true, "signedIn": true, "enrollment": "本人" }
```

| enrollment | 意味 |
|---|---|
| 本人 | ログインした人の受講に記録している（あるべき状態） |
| 開発用 | `DEV_ENROLLMENT_ID` に記録している（本番では消す） |
| なし | 記録先が無い。端末内だけ |

## 受講中の照合

受講中は3秒ごとにカメラを見て、**2回続けて外れたら再生を止めます**。
映像も静止画も顔の特徴量も、端末の外へは出しません。
サーバへ送るのは「外れた理由」だけです。

見るものは3段です。重い順に間引いてあります。

| いつ | 何を見るか | 捕まえるもの |
| --- | --- | --- |
| 3秒ごと | 明るさ・ばらつき・前の絵との差 | 暗くした・**のっぺり（塞いだ）**・止まっている |
| 6秒ごと | **顔があるか／何人か**（モデル） | 手で塞いだ・人が居ない・2人以上写っている |
| 30秒ごと | **登録した本人か**（モデル） | 別の人が代わりに座っている |

**顔があるかは毎回見ます。**間引くと、外れた回と見ていない回が交互になり、
2回続けて外れることが無くなって、いつまでも止まりません（実際そうなっていました）。

**別人と分かったときは、その1回で止めます。**本人照合は30秒に1回なので、
2回続けて外れるのを待つと、1分ものあいだ別人が受講できてしまいます。
横を向いた一瞬で止めないよう、その場でもう一度だけ確かめてから止めます。

止める・止めないの判断は `src/lib/verifyGate.ts` に切り出してあり、
画面もカメラも無しで試験できます（`tests/face.mts`）。

モデルは `public/models`（3つで約6.7MB）。端末の中で動きます。
はじめて開くときだけ落ちてきて、あとは端末に残ります（`@vladmandic/face-api`）。

**同じ人と見なす距離は 0.5** です（`SAME_FACE`）。face-api の目安は 0.6 ですが、
点検（`tests/e2e-face.mjs`）で別人どうしの距離を測ると **いちばん近い組で 0.58** でした。
0.6 のままだと、その組が「同じ人」になってしまいます。
受講の記録は法で決まった教育の証なので、0.5 まで厳しくしています。
本人が弾かれるようなら、上げるのはここだけです。

**モデルが読み込めないあいだは、視聴時間を数えません。**
見分けが付かないまま時間だけ積み上がると、受講の記録が意味を失うためです。
画面の上に「照合の支度をしています」と出ます。

**受講の準備の顔写真も、本当に顔が写っているときだけ登録できます。**
ここを素通しにすると、机でも壁でも「登録済み」になり、
受講中の照合が比べる相手を持てません。

### 点検

`tests/e2e-face.mjs` が、本物の写真をブラウザに読ませて本物の判定を呼びます。

- 6枚の写真すべてで顔を見つけ、特徴量128を取れる
- 手でレンズを塞いだ色（一色）からは顔が見つからない
- 同じ顔どうしの距離はゼロ
- 部屋を暗くしても本人と分かる（距離 0.19）
- 別の人どうしは、すべて 0.5 より遠い（0.58〜0.86）

## 端末を人から人へ渡すとき

現場ではタブレットを回して使います。端末の中に置いている記録
（受講の準備＝氏名・生年月日・顔の特徴量、視聴時間、実務の成績、
間違いノート、途中経過）は、渡した時点で**前の人のもの**です。

- **受講の準備は人ごとに分けて持ちます**（`ashiba.prep:<ユーザーID>`）。
  同じ端末を2人で使っても混ざりません。
- **ログインしたとき**に持ち主が変わっていれば、前の人の記録を消します。
- **ログアウトしたとき**も消します。ログアウトは「次の人に渡す」ボタンです。

消さないと、前の人の氏名で受講したことになったり、
前の人の視聴時間を引き継いで規定時間を満たしたことになってしまいます。
サーバ（Supabase）にある記録は本人に紐づいているので消しません。
音の入切と「更新のお知らせを見たか」は端末の設定なので残します。

仕組みは `src/lib/device.ts`（`claimDevice` / `wipeDevice`）と
`src/lib/prep.ts` にあります。

## 受講（enrollments）の作り方

ログインした人に受講が無ければ、**1件だけその場で作ります**（`src/lib/enrollment.ts`）。
決済がまだ無いので、いまは誰でも受講できる形です。

席（`seats`）を売る形にするときは、ここで受講コードの引き換えを見るようにします。
`0004_auth.sql` の索引は `seat_id is null` の受講だけを1人1件に絞っているので、
席つきの受講は複数持てます。

## 試験

| 何を | どこで |
|---|---|
| 通す道・止める道の切り分け | `npm run test:authgate` |
| ログインしないと入れないか／ログイン画面が使えるか | `npm run test:e2e:auth` |

E2E は嘘の繋ぎ先で立てたサーバに対して動きます。
本物の Supabase は要りません（「入れない」ことを確かめるにはこれで足ります）。
