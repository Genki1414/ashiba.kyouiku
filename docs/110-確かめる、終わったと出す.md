# 110　決める操作は、全部「確かめる → 終わった」を通す

2026-09-10。げんきさん。

> 請求書払いで申し込む とか、ほとんどのユーザーが行う操作全般なんだけど、
> 確認表示や完了表示のポップアップがない。
> ユーザーが操作を行う部分を全て洗い出して、全てに確認表示・完了表示のポップアップを付ける

## なぜ

押す所は、指が触れただけでも効く大きさで並んでいる。**押した瞬間に効くと、
押し間違いに気づく間が無い。**申込みなら請求書が出る。配るなら隣の人に渡る。

終わったことが出ないのも困る。静かに書き換わるだけだと、効いたのか分からず
もう一度押す。二重に申し込む。

教育担当者の付け外しにだけ付けてあった札（`AskDone`。docs/108 の少し前）を、
**サーバに書く操作の全部**に広げた。

## 洗い出し

サーバに書く（POST する）画面は 24 ファイル。押す所は約 40。

### 教育担当者（受講管理）

承認する・却下する・受講コードを配る（2か所）・対応済みにする・現物を確認した・
承認に戻す・事業者名を変更・参加コードを再発行・修了証を発行／取り消す・
退職として登録・担当者の付け外し・事業者を登録。

### 運営

入金を確認・申込みを取り消す・候補日を送る・つなぎ先を入れる・修了にする・返す・
クーポンを作る／停止／再開・支払先を追加・個人情報を削除・
実務トレーニングを付ける／取り消す・リッチメニューを配る・請求書を知らせる・
担当者の付け外し（元帳）。

`window.prompt` を使っていた所（つなぎ先・返す理由）は、札の中に書く欄を出す形にした。
prompt は字が小さく、スマホでは画面の外に出ることがある。

## 通さないもの

**受講の邪魔になる所には挟まない。**

| 何 | なぜ |
| --- | --- |
| 確認問題の答え・視聴の進み・実務トレーニングの手 | 1問ごとに札が出ると教材にならない |
| 修了試験の途中の問い | 同上。**最後の1問だけ**「採点しますか」 |
| 受講の準備（同意→顔→はじめる） | 同意の画面そのものが確かめる所 |
| さがす・絞る・クーポンの確認 | 読むだけ。何も変えない |
| ログイン・引き換えコード | ログインそのものが画面 |
| お知らせの「読んだ」印 | 開いた時点で付く。押す所が無い |

## 作り

`src/components/AskDone.tsx` の1つ。

- `run` が `false` を返したら閉じる（断りの理由は元の画面に出る）
- `run` が `{ done, doneBody }` を返したら、終わった字をそれに変える
  （申込みの「請求書は1通にまとめます」など、返事を見ないと書けないもの）
- `after` は「閉じる」を押したあとに動く。**画面を移す操作は、終わった札を見せてから移す**
  （先に移すと札ごと消えて、終わったことが出ない）
- 同じ理由で、終わると画面が入れ替わる所（`/join`）は、札を画面の外に置いてある

## 見張り

`tests/api-shape.mts`

- POST する画面を全部見て、`AskDone` が無ければ**理由を書いた表に載っていること**を求める。
  新しい画面で POST を足したら、ここで止まる
- 名指しされた操作（申込み・配る・使う・発行・入金確認・削除…）が、札を通っているか
- `window.prompt` / `confirm` を使っていないか

ブラウザ通し検証は、押したあとに札を押す手順（`confirmDone`）を各台本に足した。
「確かめる前には送らない」も見ている（`e2e-order-multi`）。
