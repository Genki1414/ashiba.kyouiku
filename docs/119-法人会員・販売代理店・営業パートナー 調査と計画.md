## 4. データベースの変更計画

- 移行 0040〜。いまの表は消さない・列の意味を変えない。足すだけ。
- `orders.method` の enum に `ticket` を足す（`alter type … add value`）。既存の `card`／`invoice` の挙動は変わらない。
- 受講の門番・修了証の門番は変えない。チケットで作った注文も `status='paid'` なので、そのまま通る。
- チケットは**残高の列を1つ持たず、ロットごとに残額と失効日**。消費は `for update` で古い順。履歴は ticket_txns に全部。
- 金額は全部 int（円）。税抜で持ち、税込は出すときに計算（請求書と同じ考え）。
- RLS：法人会員は自社の契約・ロット・履歴だけ。営業パートナーは referrals で自分に紐づく会社の「社名・プラン・契約日・状態・月額・報酬」だけ。振込先は本人と運営だけ。**画面で隠すのではなく、サーバの口と RLS の両方で止める**（いまの方針どおり）。
- 2店の共有：表は共有のまま。LP と申込みの入口は店ごとに出し分け、契約に「どの店から入ったか」を1列持つ（集計のため）。**認証・データベースの共通化は、もう共通なので新しい作業は無い。**

## 5. 決済への影響

- いまの本線（請求書払い＋運営の入金確認）で、**月額前払いはそのまま回せる**。毎月1日に対象月の請求書を自動で起こし、運営が入金を確認した瞬間に `pay_contract_month` が走る。既存の「入金を確認した」と同じ押し方。
- カードの月額自動引落は Stripe Billing（Subscription）が要る。いまの Checkout とは別物で、webhook の種類（`invoice.paid`／`invoice.payment_failed`）も増える。**鍵が未設定の現状では後回し**。設計は入金 id で冪等にしてあるので、あとから足せる。
- 代理店ショップの代金の受け取り手（本部が受けて代理店に差益を払うのか、代理店が自分で受けるのか）は決済の主体・返金責任・インボイスに関わる。**未確定のまま本番決済は始めない**（指示書6・16）。フェーズ1では「代理店が自社の顧客ぶんを、自分のチケットで申し込む」形（代金は代理店と顧客の間で直接）だけ作り、ショップでの決済は後ろへ。
- 返金・チャージバック：`refund_contract_month` でロットの残額を減らし（消費済みなら負にせず調整行を残す）、報酬を調整行で打ち消す。

## 7. 技術的な課題

1. **月額の自動化の土台が無い。** いまは注文1回ごとの入金確認。毎月の請求書の自動起票、満了・更新、失効の処理は「時刻で動く仕組み」が要る。Vercel Cron（1日1回）で起票と失効を回す。手で押す道も残す。
2. **チケット消費の同時実行。** 担当者2人が同時に申し込むと残高を超える。`spend_tickets` を行ロック付きの SQL にし、画面の計算は見せるだけにする（いまの use_coupon と同じ）。
3. **報酬の「確定」と「見込み」。** 入金があった月の行だけ確定。契約があるだけでは見込み。締め日・支払日は運営の設定で動かせるようにする。
4. **Stripe Billing は未経験の領域。** 鍵が入り次第、テストモードで月額を1回通してから。フェーズ1は請求書払いで成立させる。
5. **2店で入口が違うが、表は同じ。** 法人会員の名簿は店を問わず1つ。LP と価格の見せ方だけ店で変える。
6. **見張りの追加。** api-shape に「金額は int」「チケットを負にしない」「振込先は本人と運営だけ」「見込みと確定を混ぜない」を足す。

## 8. 仕様上の未確定事項（独断で決めない）

指示書16に加えて、実装の形に効くもの。

- **資金決済法。** 会費の2倍のチケットを12か月有効で渡すと、「前払式支払手段（自家型）」に当たる可能性が高い。有効期間が**6か月以内なら適用除外**。12か月で行くなら、基準日（3月末・9月末）の未使用残高が1,000万円を超えた時点で届出と発行保証金の供託が要る。**有効期間を6か月にするか、12か月のまま届出を前提にするかは、げんきさんの判断**。表は失効日を持つので、どちらでも動く。
- 代理店のチケットは「第三者に販売」するので、自家型ではなく**第三者型**に見える。こちらは残高に関わらず登録が要る可能性がある。法律の確認が先。
- 途中解約・契約終了後の残高・自動更新の条件。設定で切り替えられる形にするが、**既定値を何にするか**。
- 代理店ショップの代金の受け手（上記5）。
- 営業パートナーへの報酬の税務（源泉徴収の要否、支払調書、インボイス）。
- 営業パートナー契約終了後の継続報酬。
- 協力会社の社員が受けた修了証の名義・記録の保存先（親会社の名簿に載せるか、協力会社の名簿か）。
- 法人会員への「教育費削減額」の出し方（通常価格との差で出す。コードに単価があるので計算はできる）。

## 9. 最短で販売を始めるための範囲

**1月末に「月額会費を払って、チケットで受講コードが買える」状態**にするなら、ここまでで売れる。

- プラン（運営が足せる）
- 法人会員の申込み（紹介コード欄つき）→契約→初月の請求書
- 運営の「入金を確認した」で、チケット付与と報酬登録が一度に立つ
- 法人マイページ（残高・失効予定・履歴）。社員管理と受講管理は /admin
- /order で「チケットで払う」。足りなければ不足額を出して請求書払いに戻す
- 営業パートナーの登録・紹介コード・マイページ（確定／見込み）
- 運営の経営ダッシュボード（MRR・会員数・報酬控除後）と報酬の締め
- 販売代理店は「契約・付与・自社顧客ぶんの申込み」まで。ショップはフェーズ2
- LP 3枚
- 特商法・規約の改定（確定した条件だけ）

**やらないこと（後ろへ）**：カードの自動引落、代理店ショップでの決済、報酬の自動振込、ロゴ・QR、CSV、分析。
