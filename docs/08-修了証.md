# 修了証

## 出せる条件

サーバが見ます（`/api/cert`）。端末の言い分では出しません。

1. 学科の**全単元**の確認問題に合格していること
2. **修了試験**に合格していること（20問中16問）

足りないときは、何が足りないかを画面に出します。

## 様式

プロトタイプ（`handoff/ashiba-app-v16h.tsx` の `drawCert`）のままです。
`src/components/edu/drawCert.ts`。

- 横1240px。**縦は科目の数で伸びます**
  （固定にすると、科目名が長いときに下の署名欄と本文が重なります）
- **発行名義は決まっています。** 刷ったら印だけ押してください

| | |
|---|---|
| 事業者名 | 東北三上機材株式会社 |
| 教育実施責任者 | 中川元基 |

この教材は外販しますが、**特別教育を実施したのは東北三上機材株式会社**です。
修了証はその名義で出します。受講する会社の名義ではありません。

> 受講者がどの会社の人かは `companies`（事業者）で分けています。
> あれは**名簿と参加コードの話**で、修了証の名義とは別です（docs/10）。

名義は `src/lib/issuer.ts` にあります。Vercel の設定は要りません。
変わったらそのファイルの2行を直すか、環境変数
`CERT_ISSUER_NAME` / `CERT_ISSUER_RESPONSIBLE` で上書きしてください。

## 証明番号

`AT-西暦月-通し番号` の形です（例 `AT-202608-00001`）。
番号は**データベースで採ります**（`next_cert_no`）。
外販なので、会社をまたいでもぶつかりません。

もとは受講IDから4桁を作っていましたが、ひと月に1万件を超えると必ずぶつかり、
ぶつかると `cert_no` の一意制約に当たって**発行できなくなる**ので直しました。
昔の4桁の番号も、照会できるように受け付けます。

番号は**発行したときに決まります**。発行前の画面には出ません。

## 照会（/verify）

元請や監督署が「この番号の修了証はあるか」を確かめる画面です。
**ログインが要りません。** こちらのアカウントを持っていない人が開くためです。

そのぶん、**氏名は頭の1文字だけ**にしてあります。
番号を総当たりされても、名前が漏れないようにするためです。
本人か確かめたいときは、手元の紙と見比べてもらいます。

## 入金との関係（要・確認）

もとの決まり（`0003_rules.sql`）は、**受講コードに紐づく注文が入金済みでなければ
修了証を出さない**というものでした。請求書払いでも資格証だけは止める、という趣旨です。

ただ、いまはまだ決済の仕組みがありません。
自分で登録した人は注文そのものが無いので、
もとの決まりのままだと**誰にも修了証が出せません**。

そこで `0005_cert.sql` で、こう変えました。

| 受講 | どうするか |
|---|---|
| 受講コードがある | **これまでどおり**入金済みでなければ出さない |
| 受講コードが無い | いまは通す（社内での無償利用とみなす） |

**決済を入れて席を配る形にしたら、後半の分岐を消してください。**
そうすれば、もとの決まりに戻ります。

## 試験

| 何を | どこで |
|---|---|
| 出せる条件・証明番号・紙の大きさ | `npm run test:cert` |
| 出せないときの言い方・照会の画面・様式が崩れていないか | `npm run test:e2e:cert` |

様式の試験は、見本を描いて**署名欄の高さに本文が入り込んでいないか**を画素で見ています。
科目が増えたときに重なる不具合を、そこで捕まえます。
