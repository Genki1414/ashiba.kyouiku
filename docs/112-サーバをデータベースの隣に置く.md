# 112　サーバを、データベースの隣に置く

2026-09-10。げんきさん
「マイページ 6秒／続きから受講 2.5秒／請求書発行 4秒／運営 2.5秒」。

## 測った

`/setup` に「データベースまで1往復」を出して、本番で測った。

```
！ データベースまで1往復  219ms  ／ 繋ぎ始め 242ms
```

**219ms。**手元（同じ機械の中）なら1msも掛からない。
つまり、聞くたびに**太平洋を渡っていた。**

繋ぎ始め 242ms と1往復 219ms がほぼ同じなので、
握手が重いのではなく、**ただ遠い。**

## なぜ遠かったか

`vercel.json` を置いていなかったので、サーバの場所は既定のまま
（米国東部）だった。Supabase は東京にある。

画面を1枚出すのに、いくつも聞きに行く。1回ごとに 219ms 乗る。

| 画面 | 聞きに行く回数 | 待ち時間だけで |
| --- | --- | --- |
| マイページ | 7回ほど（4つの口が同時に動く） | 1.5秒＋ |
| 受講管理 | 同上 | |

聞く回数はここまでで減らしてきたが（10往復→1往復など）、
**1回あたりが 219ms では、減らしても効きが薄い。**
場所を寄せれば、同じ回数のままで 40分の1 になる。

## 直したこと

```json
{ "regions": ["hnd1"] }
```

`hnd1` は東京。**データベースと同じ場所**にサーバを置く。

見張りの中継（middleware）は、これまでどおり世界中の近い所で動く
（場所の指定は、サーバの処理だけに掛かる）。

## 確かめ方

`/setup` をもう一度開く。

| | 前 | 狙い |
| --- | --- | --- |
| データベースまで1往復 | 219ms（橙） | **10ms 以下（緑）** |
| サーバの場所 | （出していなかった） | hnd1 |

サーバの場所も画面に出すようにした。**下がらなければ、Supabase が
東京に無い**ということなので、そのときは Supabase 側を見る。

## 残っていること

場所を寄せても、**冷えているサーバの立ち上がり**は残る。
人が来ない時間が続いたあとの1回目は、それだけで1〜2秒かかる。
そこは、まず場所を直してから測り直して決める。
