# 更新のお知らせ

アプリを開いたとき、前に見たときから何が変わったかを画面で知らせます。
一度「分かった」を押せば、次の更新まで出ません。

## 手を入れたら、ここに1件足す

`src/content/changelog.ts` のいちばん上に足します。**これを忘れると知らせが出ません。**

```ts
export const RELEASES: Release[] = [
  {
    v: "2026-08-22-1",        // 日付＋その日の通し番号。これが「見たかどうか」の目印
    d: "2026年8月22日",       // 画面に出る日付
    title: "第2章の当たり判定を直した",
    items: [
      { k: "直した", t: "第2章で、踏板の的が小さくて押しにくかった" },
      { k: "足した", t: "第2章に◯◯を足した" },
    ],
  },
  // ...これまでの分は下に残す
];
```

- `v` は同じ日に何度も出すなら `-2`, `-3` と増やします
- `k` は `足した` か `直した` の2つだけ
- `t` は**現場の人が読んで分かる一言**で書きます。
  どの画面の話かが分かるように、「第1章で」「段取りの」から始めると読みやすいです

## 出し方の決まり

| 相手 | 出るもの |
|---|---|
| 初めて開いた人 | いちばん新しい**日ぶん**（その日に何度直しても、まとめて1回） |
| 前に見たことがある人 | 前に見た目印より新しいものを、新しい順に全部 |
| 目印が分からない（消した・古すぎる） | いちばん新しい日ぶん |
| 最新まで見ている人 | 出さない |

見たところは端末が覚えます（`localStorage` の `ashiba.seen-update`）。
覚えられない端末（プライベートモードなど）でも、その回はちゃんと出て、閉じられます。

閉じたあとでも、章の一覧のいちばん下の**「更新の一覧を見る」**（`/updates`）から読み返せます。

いま出ている版は `<body data-app-version="...">` で分かります。
実機で「新しくなっているか」を見るときに使えます。

## 試験

| 何を | どこで |
|---|---|
| 出し分けの決まり | `npm run test:changelog` |
| 実際に出る・閉じたら出ない・新しいのが来たらまた出る | `npm run test:e2e:update` |

ほかのブラウザ試験は、最初の1回だけこの知らせを閉じてから進みます
（実機と同じ動きなので、そのままにしてあります）。
