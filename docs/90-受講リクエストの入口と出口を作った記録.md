# 90 受講リクエストの入口と出口を作った記録（2026年9月7日）

げんきさんの「ユーザーが講座の受講コード入力画面で、教育担当者に対し受講リクエストを
送れるようにする。担当者側は誰がどの講座をリクエストしてるか分かり、そこから申し込み可能とする」。

## もともと出来ていたこと

0025（受講リクエスト）は本番にも入っている。表も関数もある。

- 本人が**マイページ**から、講座ごとに「受けたい」を送れる
- 担当者の画面に一覧が出て、「対応済みにする」で閉じられる

## 足りなかったのは、入口と出口

**入口。**「受けたい」を送れるのはマイページだけだった。
しかし**コードを渡されていない人が実際に開くのは `/join`（受講コードを入れる画面）**で、
そこには「コードを持っていない場合は、会社の教育担当者に聞いてください」と
**書いてあるだけ**だった。聞く手立ては画面の外（電話か口頭）にしかない。
いちばん詰まる場所に、道が無かった。

**出口。**担当者の画面は一覧を出して閉じられるだけで、
そこから**申し込みにつながっていなかった**。
しかも1人1行で並ぶので、同じ講座に3人来ていても3行に散り、
**何席買えばよいのかが読み取れない**。

## 作ったもの

### 入口：受講コードを入れる画面に「④ コードをもらっていないとき」

- 受けたい講座を選んで送ると、いま在籍している会社の担当者の画面に出る
- **73講座あるので、講座名でさがせる**ようにした。探せないと押す物にたどり着けない
- 送ってあるものは「送信済み（取り消す）」に変わる
- **もう席がある講座には「送る」を出さない**（「席あり」と出す）。二重に頼むことになる
- **在籍しているときだけ出す。** 会社に居ないと誰宛か決まらない
- 席（受講コード）はここでは作らない。担当者がいつもどおり用意する

読むのは `/api/course-request` の GET（新しく足した）。
マイページ（`/api/mypage`）でも同じことは分かるが、あちらは受講の進み具合まで
数えるので重い。ここは名前と印だけを返す。

### 出口：担当者の画面を講座ごとにまとめて、そのまま申し込む

- **講座ごとにまとめた。**「高所作業車 2名／田中一郎・佐藤次郎」と出る
- **「2名ぶん申し込む」**で、`/order?courseId=kousho&seats=2` へ。
  講座と席の数が入った状態で申し込み画面が開く
- 数はあちらで直せる。押さえつけない（受けない人が混じることもある）
- 「対応済みにする」は、その講座のぶんをまとめて閉じる。
  1件ずつ押させると押し忘れが残る

申し込み画面（`/order`）は、前から `courseId` は受け取っていた。
**`seats` も受け取る**ようにした。1〜999 の整数以外は無視する
（画面から来た数をそのまま信じない）。

## 見張り

**0025 には、テストが1件も無かった。** 一緒に作った。

`supabase/tests/course-request.sql`（**23件通過**）
- 会社に居ない人は送れない（誰宛か決まらない）
- 連打しても、同じ講座に開いているものは1件だけ
- 別の講座は別に立つ／無い講座ははじく
- 押し間違いを取り消せる。**対応済みのあとは取り消せない**（もう届いている）
- 対応済みを戻せば、また送れる
- **よその会社のリクエストは動かせない**
- ログインした人から直に関数を呼べない（anon も authenticated も不可）
- RLS が入っている
- 人を消したら、リクエストも一緒に消える（3年で消すときに残らない）

`tests/api-shape.mts`
- GET が `courseId / name / short / requested / hasSeat` を返しているか
- **会社の番号を画面から受け取っていないか**（受け取ると、よその会社宛に送れてしまう）
- `/join` がそれを読んでいるか、在籍しているときだけ出しているか
- 担当者の画面が `/order?courseId=…&seats=…` へ渡しているか
- 申し込み画面が席の数を受け取り、そのまま信じていないか

`tests/e2e-admin.mjs`
- `/join` で講座が並び、さがせて、送れて、送信済みが取り消しに変わる
- もう席がある講座には「送る」が出ない
- 担当者の画面で、3件が講座ごとに2つにまとまる。人数と名前が出る
- 「2名ぶん申し込む」のリンクに、講座と人数が入っている

## 直したこと

画面を見て気づいた。`/join` の見出し番号が**③で重なっていた**
（既存の「③ 受講コードを入れる」と、足した「③ コードをもらっていないとき」）。
足したほうを**④**にした。
