# 93　特別教育ドットコム（店を二つにする）

げんきさんの決めごと（2026-09-07）。

> 特別教育と職長教育は別システムとして足場屋さん以外にもリリースしていく
> 足場屋さん向けが足場屋革命／それ以外の業種向けが特別教育ドットコム
> 基本的には足場屋革命側を正とする
> 特別教育ドットコムでは足場特別教育も一覧にいれる（検索で出る）

## 1　決まったこと

| | 足場屋革命 | 特別教育ドットコム |
| --- | --- | --- |
| 売り先 | 足場屋さん | それ以外の業種 |
| 講座 | 73講座 | **同じ73講座**（足場も入る） |
| 実務トレーニング | 出す | 出さない |
| 講座の並べ方 | 足場・職長を大きな札、残りは「その他特別教育」 | 全部を法令の号順に平らに並べ、探す窓ひとつ |
| 修了証 | 同じ様式・同じ発行者（東北三上機材株式会社） | 同じ |
| 席・名簿・請求 | 同じ仕組み | 同じ |

**足場屋革命が正。** 講座も、席も、修了証も、migration も一つ。

## 2　なぜアプリごと複製しなかったか

げんきさんの言い方は「特別教育関連をコピーするだけのイメージ」だった。
ファイルごと複製すると、こうなる。

- 講座を1本足すたびに、二回登録する（登録の口は12か所ある）
- 法令が変わったら、二回直す
- 画面を1か所直したら、二回直す
- migration を二回当てる

**必ず片方が古くなる。** 実際にこの前やった。「その他特別教育」の探す窓を
上に出したとき、同じ物が2か所にあったせいでホームだけ直し忘れ、
げんきさんに「検索がまだ最下部にある」と言われた。2か所でそうなった。
アプリまるごとなら、もっと起きる。

だから **中身は一つ、店を二つ** にした。お客さんから見れば別ドメイン・
別の名前・別の表紙で、げんきさんの直しは一回で済む。

## 3　作り

`src/content/brand.ts` に、店ごとの名前と表紙をまとめた。
変わるのはここに書いてあるものだけ。

    name / shortName / eyebrow / lead / title / manifestName /
    description / metaDescription / mailFrom / notifyPrefix /
    training（実務トレーニングを出すか）/ flatList（平らな一覧にするか）

どちらの店かは環境変数 `NEXT_PUBLIC_BRAND` で決める。
**書かなければ足場屋革命。** いまの本番は何も足さなくてよい。
秘密ではないので `NEXT_PUBLIC_` で構わない（画面にそのまま出る文字）。

名前が出る所は、全部ここから取るようにした。

| 出る所 | ファイル |
| --- | --- |
| タブと検索の題・アプリ名 | `src/app/layout.tsx` |
| ホームの見出しと表紙 | `src/app/page.tsx` |
| ホーム画面に追加する名前 | `src/app/manifest.ts`（public から移した） |
| ログイン画面の見出し | `SERVICE_NAME`（`src/content/courses.ts`） |
| ログインのメールの差出人 | `src/content/authMail.ts` |
| 知らせの頭【 】 | `src/lib/notifyText.ts` |

### 差出人の住所は変えない

`noreply@ashibase.jp` のまま。名前だけ変える。ドメインを増やすと
送信の認証（SPF・DKIM）をもう一度通すことになり、通るまでメールが
1通も届かない。届かないより、名前のドメインが違うほうがまし。

### 平らな一覧は、法令の号順

COURSES の並びは足場屋革命の看板順で、足場がいちばん上にある。
そのまま出すと、塗装屋さんや解体屋さんが開いて最初に見るのが足場になり、
「足場屋のところか」と読まれる。

売り文句で決めずに、**目録（法令）の号順**に置いた。うちの都合が入らないし、
下に並ぶ「まだ作っていない目録」と同じ順になるので、探すときに迷わない。
先頭は職長教育（特別教育ではないので号を持たない）、次が第1号のといし。
足場は第39号の位置に出る。**一覧にも入っているし、探しても出る。**

### 5-1　環境変数

**足場屋革命（ashiba-kyouiku-nkdr）から値をそのまま写すもの。**
同じDB・同じ名簿・同じ修了証・同じ請求にするため、ここは必ず同じ値にする。
別の値を入れると、店ごとに名簿が割れる。

| 名前 | 種別 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Config |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Config（anon public は Config でよい） |
| `SUPABASE_SERVICE_ROLE_KEY` | **Secret** |
| `STRIPE_SECRET_KEY` | **Secret** |
| `STRIPE_WEBHOOK_SECRET` | **Secret**（5-3 を読むこと） |
| `EXAM_SECRET` | **Secret**。入れないと本番で修了試験が出ない |
| `OWNER_EMAILS` | Config |
| `CERT_ISSUER_NAME` / `CERT_ISSUER_RESPONSIBLE` | Config（入れているなら） |
| `LINE_TOKEN` / `LINE_TO` | **Secret**（入れているなら） |

**この店だけ違う値にするもの。**

| 名前 | 値 |
| --- | --- |
| `NEXT_PUBLIC_BRAND` | `tokubetsu` ← これを入れないと足場屋革命の見た目のまま出る |
| `NEXT_PUBLIC_SITE_URL` | 新しいドメイン（`https://…`） |
| `SITE_URL` | 同上 |

配信ごとに変わる住所へ飛ぶ。**Supabase の許した住所に入っていないと弾かれる。

### 5-2　入れたあと、必ず作り直す

`NEXT_PUBLIC_BRAND` は**組み立てるときに画面へ焼き付く。**
環境変数を足しただけでは、すでに出来ている配信は変わらない。
入れてから Deployments → Redeploy（または次の push）。

### 5-3　Stripe の webhook

いまの webhook の宛先が kyouiku.ashibase.jp のままでも、**支払いは通る。**
webhook は注文の行を Supabase で「入金済み」に直すだけで、
その Supabase は両方の店で同じものだから。

新しいドメインにも webhook の宛先を足すなら、**Stripe がその宛先ごとに
別の署名の鍵を出す。**そのときは、その鍵を
`tokubetsu-kyouiku` の `STRIPE_WEBHOOK_SECRET` に入れること。
古い鍵のままにすると署名が合わず、**払ったのに入金済みにならない。**
足さないなら、上の表のとおり同じ値を写すだけでよい。

### 5-4　ドメイン

**`tokubetsu-kyouiku.com`**（げんきさんが取得。2026-09-09）を
`tokubetsu-kyouiku` に当てる。`ashiba-kyouiku-nkdr`（kyouiku.ashibase.jp）は**触らない**。

当てるときに、3か所を同じ値にそろえる。1つでも欠けると、
パスワード再設定のメールから戻ってきた人が弾かれる。

| 所 | 値 |
| --- | --- |
| `src/content/brand.ts` の `TOKUBETSU.site` | `https://www.tokubetsu-kyouiku.com`（記入済み） |
| Vercel の `NEXT_PUBLIC_SITE_URL` と `SITE_URL` | 同じ（Production） |
| Supabase の Redirect URLs と Site URL | `https://www.tokubetsu-kyouiku.com/**` |

**www が本番。**apex（tokubetsu-kyouiku.com）は www へ 308 で転送する形で
登録してある。だから住所は www を書く。apex を書くと、パスワード再設定の
リンクが1回転送されてから届く。

DNS は Vercel の「View DNS configuration」に出る値をそのまま入れる。
ふつうは apex が A（76.76.21.21）、www が CNAME（cname.vercel-dns.com）。
入るまで Vercel は Invalid Configuration と出す（数分〜数時間）。
環境変数を入れたら **Redeploy**（`NEXT_PUBLIC_` は組み立てるときに焼き付く）。
