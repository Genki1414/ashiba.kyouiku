# 115　支払期限と、黙って落ちる記録

2026-09-11。げんきさん

> 支払い期限は請求書発行から1週間後。支払い確認が取れなければ受講不可
> まとめて片付けて

前の日の点検（リリースの壁）で挙げた3つと、記録の取りこぼしを片づけた記録。

## ① 支払期限を1週間にして、言うことを1つにした

### 何が起きていたか

同じ取引について、画面ごとに違うことを言っていた。

| どこ | 前 |
| --- | --- |
| 特商法・支払時期 | 支払期限は定めていません |
| 申込み画面の上 | 支払期限は設けていません |
| **同じ画面の下（申込み履歴）** | **支払期限 2026年10月31日** |
| 請求書 | お支払期限　確認次第 |
| 規約 第4条 | 支払期限は請求書に記載します（請求書には日付が無い） |

実体としては期限は**あった**（30日後の月末を `due_date` に入れていた）。
「定めていない」と書きながら期限を持ち、画面によっては日付を出していた。

支払時期は特定商取引法の必須記載事項なので、ここが食い違っていると表示が虚偽になる。

### 決めたこと

**請求書の発行から1週間。**確認が取れなければ受講不可。

請求書は申し込んだその場で出る（あとから発行する手順は無い）ので、起点は申込みの時刻でよい。

### 日本の日付で切る

```
2026-09-11 08:00（日本）＝ 2026-09-10 23:00（世界標準時）
```

世界標準時のまま切ると、**日本の朝9時前に申し込んだ人の期限が1日手前になる。**
30日後の月末だった頃は月をまたぐ時だけの話だったが、1週間になると毎日ずれる。
1日でも短く言えば、払ったのに期限切れ、が起きる。

`dueDateStr()` が日本の日付で返す。境目（未明・夜・月またぎ・年またぎ）は
tests/pricing.mts が見ている。

### 過ぎたことが分かるようにした

決めたからには、過ぎたことが分からないと動けない。
運営の申込み一覧で、期限を過ぎた入金待ちに「期限超過」と赤く出す。

**自動では取り消さない。**振込と行き違っていることがあるので、見てから決める。

## ② カード払いの入金が、静かに消えることがあった

`stripe/webhook` が、データベースの読み書きの失敗を受け取っていなかった。

```ts
const { data: order } = await supabase...   // error を受けていない
if (!order) return NextResponse.json({ ok: true, skipped: "no order" });  // 200
```

Stripe は **200 を受け取ると、その知らせを二度と送ってこない。**
つまり読み書きに失敗すると、カードは切れているのに入金が立たず、
受講コードも出ないまま確定する。しかも記録に何も残らない。

請求書払いの同じ処理は失敗をちゃんと返していた。ここだけ抜けていた。
docs/100「読めなかったを0件に化けさせない」と同じ話が、いちばん高い所に残っていた。

直したこと。

- 読めなかった・立てられなかったら **5xx を返す**（Stripe が送り直す）
- 失敗は必ず記録に残す（console.error）
- 0件を、いつも成功にしない。**入金待ちが残っているか**で見分ける
  （二度目の知らせなら残っていない。失敗なら残っている）
- 席を出せなかったときも断る。ただし**要る枚数で見る。**
  0件で断ると、席を出さない申込み（実務トレーニングの利用権）で
  送り直しが終わらなくなる

## ③ 実務トレーニングの申込みに、法務の表記が無かった

`/train` には規約・個人情報・特商法へのリンクが1つも無かった（`/order` には有る）。
お金が動く画面から法務表記に行けない状態だった。特商法は買う前に見られることを求めている。

実務トレーニングの値段も、特商法の価格一覧に**1件も載っていなかった。**
請求書には独立した品目として出るのに、値段だけどこにも書いていない。

`allPrices()` が実務トレーニングも返すようにした。売っている店でだけ載せる
（特別教育ドットコムは売っていない）。

## ④ 記録が、黙って欠けていた

元請や監督署に出すのは**データベースの記録**。それが残らなくても画面には成功と出ていた。

### 本人確認（顔照合）の控え

```ts
fetch("/api/verify-log", {...}).catch(() => {});
```

返事を捨てていた。ログインが切れて401でも、サーバが500でも、画面には何も出ず受講は進む。
あとで記録を出そうとしたときに初めて「その時間の控えが無い」と分かる。もう受け直すしかない。

返事を見て、残せなかったら受講中の画面に出すようにした。
**画面は止めない**（見ている時間は端末にも残る）が、気づける形にする。
残せた時点で消える（一時的な電波切れで言い続けない）。

### 修了試験の記録

`error` を捨てて `mode` を `"local"` のままにしていた。画面は `mode` を見ていなかったので、
**受講者には「合格」と出るのに `exams` には1行も無い。**
あとで修了証を申し込むと「試験に合格していません」と断られ、何が起きたのか誰にも分からない。

`saved` を返して、画面がそれを見るようにした。
「このままでは修了証を発行できません」とその場で伝える。

受験回数の数え直しも同じ。失敗を0と読むと、いつも1回目からになる。
