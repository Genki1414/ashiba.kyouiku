# 第1章「段取りと根がらみ」の判定仕様

`HANDOFF.md` 3章の「現場のルール」を、そのままコードにしたものの対応表です。
監修や、あとから来た人がコードを読まずに突き合わせられるように作ってあります。

実装は3つに分かれています。

| ファイル | 役割 |
|---|---|
| `src/training/ch1/layout.ts` | 割り付け（柱・スパン・内柱の決まり・ジャッキの目標値） |
| `src/training/ch1/queue.ts` | 工程キュー。何を、どの順で、どこに置くか |
| `src/training/ch1/rules.ts` | 判定。工程キューから正しい手／ファールを導く |
| `src/training/ch1/state.ts` | 状態と進行（JSONに落とせる形） |

| `src/components/training/` | 描画（盤面・部品・作業員と親方） |
| `src/components/training/scenes/Prototype.tsx` | 場面。プロトタイプの overlay を描画を変えずに移植 |
| `src/app/training/ch1/` | ゲーム画面。判定を呼んで見せ方を決める |

検査は2本あります。

- `npm run test:ch1` … 判定だけを直接叩く（78件）。正しい手順で26工程を通せること、
  下の表のファールが全部出ること
- `npm run test:e2e:ch1` … 実際のブラウザで段取りから完了まで通す
  （`npm run dev -- -p 3100` を先に起動しておく）

## ルールと実装の対応

| HANDOFF 3章 | 判定 | 分類（tag） | 重さ |
|---|---|---|---|
| 1. 段取りの順序：根がらみ手摺 → 内柱箇所の手摺 → ジャッキ | 手摺が1本も無い状態でジャッキ・内柱手摺を置くとファール | 段取りの順序 | ファール |
| 2. 内柱：端部は必ず、中間は2スパンに1本 | 出隅を内柱にする／間隔が空きすぎる／中間の本数超過はファール | 内柱の位置決め・内柱の本数 | ファール |
| 3. ジャッキ合わせ：挿す手前で計算値へハンドルを合わせる | 支柱を立てる前に場面を出す。**ゲーム中2回だけ** | — | 場面 |
| 4. 建方：出隅 → 2方向に根がらみ手摺 → 両隣の柱 | 順を飛ばすとファール。手摺は立っとる柱のコマへ | 建てる順序・根がらみの順序 | ファール |
| 5. 柱ごとの順序：離れ → 水平 → ブラケット（全箇所固定） | 離れの前に水平／水平の前にブラケットはファール | 手順の飛ばし | ファール |
| 6. 水平器は根がらみ手摺の端から少し中 | 場面の中で選ばせる。外すと親方がその場で理由を言い、技能点を引いて選び直させる | 水平器の置き場所 | ファール |
| 7. 内柱の箇所：内柱 → 600手摺 → 離れ → 水平（支柱に当てる） | 外柱の水平前に内柱を立てるとファール | 手順の飛ばし | ファール |
| 8. ブラケットは外柱から建物側へ張り出す | 内柱の箇所に掛けるとファール。**出隅は面ごとに1枚ずつ要る** | 取付位置の誤り | ファール |

## 重さの区別

`PROMPT.md` 4章のとおりに分けています。

| 種類 | 返り値 | 技能点 |
|---|---|---|
| 安全の問題 | `kind: "foul"` に `why`（なぜ危ないか）を必ず付ける | 減らす |
| 効率の問題・置き直し | `kind: "note"`。親方が一言添えるだけ | 減らさない |

ファールのときは「何が駄目か」ではなく「**なぜ駄目か**」を返します（`why`）。
画面では親方の怒り顔の横にこの文言を出します。

## 決まったこと

依頼者（現場の職人）に確認して決めた扱いです。

| 事柄 | 決定 |
|---|---|
| 水平器の置き場所を外したとき | **減点する**（−8）。プロトタイプは減点していなかったが、安全に関わるため変更 |
| 中間の内柱を余分に入れたとき | **減点する**（−8） |
| 通し見学10手目の「なぜ」 | いまの文言のままでよい |

水平器の置き場所は、場面の中で親方が理由を言って選び直させる流れは
プロトタイプのままです。そこに技能点の減点だけを足しています。

## 盤面のタップ

内柱は外柱から600mmしか離れていません（HANDOFF.md 4章の縮尺どおり）。
スマホの画面では**18pxほどしか離れない**ので、指で狙い分けられません。
縮尺は変えられないので、当たり方の側で3つ手を打っています。

1. **盤面を作業する範囲に寄せる**
   地面の四隅まで枠に入れると足場のまわりが余白だらけになるので、
   物が置かれる範囲だけを枠に入れています（`viewBoxFit`）。
   iPhone の幅で **1.5倍**大きくなりました。

2. **いまの道具で押せない場所は候補から外す**（プロトタイプの `valid` と同じ）

   | 場面 | 道具 | 押せる場所 |
   |---|---|---|
   | 段取り | 根がらみ手摺 | スパンだけ |
   | 段取り | 600手摺 | 内柱の側だけ |
   | 段取り | ジャッキ | 柱と内柱の側 |
   | 建方 | 支柱・内柱・ブラケット | 柱だけ |
   | 建方 | 手摺・踏板・600手摺・先行手摺 | スパンだけ |
   | どちらも | 移動 | 全部 |

   外しておかないと、狙った所の隣に吸い寄せられて「押していない所」が反応します。

3. **まだ置いていない方を先に取る**
   段取りのジャッキだけは柱と内柱の両方が押せます。
   同じ所を押したとき、まだ置いていない方を先に取るので、
   柱6本 → 内柱3本の順に、同じ場所を押していくだけで配れます。

押せない場所の印は薄く、済んだ場所の印は控えめに出します。

`tests/e2e-tap.mjs` が iPhone の画面幅で、印から12pxずらして押しても
狙った所が反応するかを見ています。

## 場面の並び（プロトタイプと同じ）

盤面の手が場面を開き、場面が次の場面を開く連鎖になっています。

| きっかけ | 場面 | 中身 |
|---|---|---|
| 支柱を立てる（2回だけ） | ジャッキ合わせ | 目盛と目標の帯。10刻みでハンドルを上下 |
| 「離れを見る」 | 離れ | ずれた状態から50刻みで900へ。合うと自動で閉じる |
| 「水平を見る」 | 水平器 | 置き場所を選ぶ → 気泡を合わせる。**基準側のジャッキを触るとファール（−10）** |
| 内柱を立てる | ① 次にどうする？ | 水平を先に見るとファール（−10） |
| ↓ | ② 600手摺の取付 | 取り付けの動き |
| ↓ | ③ 水平器はどこに当てる？ | 手摺に当てるとファール（−10） |
| ↓ | ④ 内柱の水平 | 支柱に当てて合わせる |

ファールの重さは2種類あります（プロトタイプと同じ）。

| どこで | 出方 | 技能点 |
|---|---|---|
| 盤面の手（置く場所・順序の誤り） | 親方の横に文字 | −8 |
| 場面の中（順序を逆にした・基準を動かした） | 怒りの画面が出て、閉じるまで進めない | −10 |

音（SFX）は `src/lib/sfx.ts` に入っています。WAVをその場で作って鳴らす方式で、
波形の式はプロトタイプのままです。各章の頭で入切でき、切ったことは端末が覚えます。

## 手摺先行工法（`/training/ch1?sk=1`）

床を張る前に手摺を上げる段取りです。通常の段取りとは3点だけ違います。

| 事柄 | 通常 | 先行手摺 |
|---|---|---|
| 出隅のブラケット | 南面・東面で1枚ずつ掛ける | **掛けない** |
| 出隅の隣のスパン | 1スパン（1,800mm） | どちらか片側を**600スパン**にする |
| 踏板を敷く前 | そのまま敷く | **先行手摺を上げてから**敷く |

出隅にブラケットを掛けないのは、出隅の柱では
**ブラケットの付くコマと先行手摺の付くコマが同じになる**ためです。
はじめに「出隅のどちら側を600にする？」と聞き、選んだ側の柱を600mmぶん出隅へ寄せます。
コマの取り合いはこの図（`CornerArt`）で見せています。

600スパンの先の柱は、順序がひとつ増えます。

    離れ → 600手摺で出隅とつなぐ → 水平 → ブラケット

600は根がらみだけでは持たないので、つないでからでないと水平器を当てても動きます。
この柱の水平は縦向き（出隅を基準に）で見るため、水平器の置き場所は聞きません。

| きっかけ | 場面 |
|---|---|
| はじめの一度だけ | 出隅のどちら側を600にするか（コマの取り合いの図つき） |
| 600スパンに600手摺を入れる | 取り付けの動き（`RailAnim corner`） |
| 600スパンの柱で「水平を見る」 | 縦向きの水平器。基準は出隅 |
| 先行手摺を上げる | 下から手摺枠を上げる動き（`SgakeAnim`） |

側を決めることと、段取りから建方への切り替えは作業ではないので点は付きません。
