# 99　複数講座のまとめ申込みと、申込みへの導線（2026-09-08）

げんきさんの2つ。

> 教育担当者画面側で受講コード申し込みの場面なんだけど、複数講座申し込み出来るようにして欲しい
>
> それと、講座画面から教育担当者画面に行く時、直接コード申し込み画面に遷移しないと導線で迷う

---

## 1　なぜ「請求書も1枚」まで直したか

受講コードは講座ごとに出るので、注文の行は講座ごとで正しい
（`orders.course_id` は1つ）。**画面だけ複数選べるようにして、
注文を3本立てるのがいちばん簡単だった。**やらなかった理由。

請求書は注文ごとに出る。3本立てれば**請求書が3枚**出る。

| 起きること | なぜ困るか |
| --- | --- |
| 振込が3回 | 振込手数料も3回。買う側が損をする |
| 1回でまとめて振り込まれる | **どの請求書の入金か分からない。**照合できない |
| 本部の「入金を確認した」を3回押す | 押し忘れると、**その講座だけ受講コードが出ない** |

3つ目がいちばん悪い。「足場は届いたのに石綿が来ない」となり、
受け取った側からは原因が見えない。担当者は運営に問い合わせるしかない。

だから **申込みは1回・請求書は1枚・振込も1回・入金の確認も1回**にした。

## 2　ひとまとめの印（0029）

    alter table public.orders add column if not exists group_id uuid;

- 注文の行は今までどおり講座ごと（受講コードは講座ごとに出る）
- 同じ申込みで作った行は、同じ `group_id`
- **1講座だけの申込みも、1行だけの group。例外を作らない**

例外を作ると、請求書と入金確認に「group のとき／ないとき」の2本の道が
できて、片方だけ直し忘れる。

### 書き忘れても壊れないようにした

入れる道が増えたときに `group_id` を書き忘れると、
**その注文だけ請求書が出ない。**仕組みで防ぐ。

    create trigger orders_set_group before insert on public.orders ...
      -- group_id が null なら、自分の番号を入れる

いまある注文は 0029 が埋めた（`update ... where group_id is null`）。
埋めておかないと、**古い請求書だけ開けなくなる。**

## 3　直したところ

| 所 | 何をしたか |
| --- | --- |
| `src/app/order/OrderClient.tsx` | 「選んでいる講座1つ＋人数」→「講座 → 人数」。講座ごとの明細と合計を、押す前に出す |
| `src/app/api/order/route.ts` | `items: [{courseId, seats}]` で受ける。同じ `group_id` で行を立てる。**知らせは申込み1件につき1回** |
| `src/app/api/owner/invoice/route.ts` | group の行を全部並べて1枚にする。合計は行ごとに割り戻してから足す |
| `src/app/owner/invoice/[orderId]/InvoiceClient.tsx` | 明細を行で並べる |
| `src/app/api/owner/orders/route.ts` | 入金の確認を group まるごと。行ごとに受講コードを作る |
| `src/app/api/stripe/checkout/route.ts` | カードも申込みまるごと1回で切る（行ごとに切ると、途中でやめられて半端が残る） |
| `src/app/api/stripe/webhook/route.ts` | 戻りも group まるごと立てる |

### 画面で気を付けたこと

- **講座を渡されていなければ、何も選ばない。**先頭を勝手に選ぶと、
  まとめ申込みでは「押したつもりのない講座」が混じる
- 講座が73本あるので**絞り込みの窓**を付けた
- **絞り込みで隠れている選択を知らせる。**絞ったまま押すと、
  画面に出ていない講座まで買うことになる
- 人数を0にしたら選択から消す。0のまま残すと、送る並びに
  「0人の講座」が混じってサーバに断られる
- 何も選んでいないうちは押せない
- 送るのは「講座と人数」だけ。**金額は送らない**（サーバが計算する）

## 4　申込みへの導線

受講コードが要ると断られた画面（`NeedSeat`）の
「教育担当者の方はこちら（申込み）」は `/admin` へ飛んでいた。

担当者があの画面で探すのは**申込みの入口**なのに、
名簿や進み具合の中から見つけることになる。

ここを押す人は、**いま断られた講座の受講コードが欲しい**と決まっている。
だから申込みの画面へ直に送り、**その講座を選んだ状態**で開く
（`src/components/OrderLink.tsx`）。札の字も
「足場の受講コードを申し込む」と、講座の名前で出す。

どの講座かは住所（`/edu/<講座>/…`）から取る。見張りはレイアウトなので
courseId を受け取れない。`RequestCourse`（docs/97）と同じやり方。

`order-group.sql` が見ていること。

    3行が1つの申込み ／ 申込みは1件（行の数ではなく group で数える）
    合計 49,500円 ／ 印を書き忘れても自分の番号で埋まる
    3行とも入金済み ／ 別の申込みは巻き込まない
    入金日時の抜けは0 ／ 印の無い注文は0

`e2e-order-multi.mjs` が見ていること（申込みの口の返事だけ差し替えて、
担当者として画面を開く）。

    足場5×4,500 ／ 職長3×7,000 ／ 石綿2×5,000
    → 小計 53,500・合計 58,850・「3講座・10名」
    **値段の違う講座を混ぜてある。**同じ値段だと、1つの単価で掛けても
    合ってしまい、間違いに気づけない

    絞り込みで隠れている選択を知らせる／絞っても合計は変わらない
    送る中身は講座と人数の並び／**金額は送らない**
    送ったら選択が空に戻る（押し直しで二重に申し込まない）
    講座を渡すと、それを選んだ状態で開く（導線）

## 6　げんきさんの実機で見てほしいこと

**本物のログインが要るので、こちらでは押せていません。**

1. 3講座まとめて申し込む → **請求書が1枚**で出るか。明細が3行あるか
2. 本部で「入金を確認した」を**1回**押す → 3講座ぶんの受講コードが出るか
3. 講座を開いて断られた画面 →「教育担当者の方はこちら（◯◯の受講コードを
   申し込む）」を押す → その講座が選ばれた状態で開くか

**Supabase の SQL Editor に `supabase/apply-all.sql` を流すこと**（版 0029）。
流さないと `group_id` の列が無く、申込みが立ちません。
