# 111　画面から画面への移りを速くした記録

2026-09-10。げんきさん「遷移速度が遅いのを改善して」。

## まず測った

製品と同じビルドを手元で立てて、押してから次の画面が出るまでを測った
（`tests/speed.mjs`）。

| 道 | 手元 |
| --- | --- |
| ホーム → 講座の一覧 | 112ms |
| 講座の一覧 → ホーム | 59ms |
| ホーム → マイページ | 38ms |
| ホーム → 受講管理 | 44ms |

**手元は速い。**手元には Supabase をつないでいない。
つまり待っているのは**画面の組み立てでも荷物の重さでもなく、
Supabase までの往復**だと分かった。だから、往復の数を数えて減らす。

## ① 受けられるかを見る所（いちばん効いた）

`learnFor` は、こう聞いていた。**順番待ちで5回。**

1. 所属（memberships）
2. 利用者の会社（users）
3. 会社の名前（companies）
4. 引き換えた席（seats）
5. その席の注文（orders）

①〜③は**断り文の「◯◯の教育担当者に聞いてください」にしか使わない**のに、
断ると決まる前に聞いていた。受けられる人（ほとんどの人）には丸ごと無駄。

席と注文は外部キーで繋がっているので、ひと息に取れる。

```
seats?select=id,orders!inner(course_id)&used_by=eq.◯◯&orders.course_id=eq.ashiba&limit=1
```

**通る人は、これ1回で終わる。**会社の名前は、断ると決まってから聞く。

## ② 講座を開くと、同じことを2度やっていた

`/edu/◯◯` を開くと、

- 外側のレイアウト（`/edu/layout.tsx`）が `canLearn()`（5往復）
- 講座の頁が `canLearn(courseId)`（5往復）

で、**同じ持ち物を2度、合わせて10往復**聞いていた。

外側のレイアウトは、**もともと置いてはいけない場所**だった。
ここは講座が分からない（レイアウトなので URL の一部を受け取れない）ので、
見られるのは「1枚でも持っているか」まで。それでは2つとも困る。

| | 何が起きるか |
| --- | --- |
| 甘すぎる | 足場の受講コードを1枚持っていれば、73講座ぜんぶ通る |
| 厳しすぎる | **実技の手引きまで塞ぐ** |

### 手引きは、まだ塞がっていた

2026-09-10 に「実技の手引きを、どの講座でも開くようにした」と報告したが、
外していたのは**内側**（`/edu/[courseId]/layout.tsx`）だけで、
**外側が残っていた。**手元は Supabase をつないでいないので素通りし、
本番でだけ塞がっていた。見張りも内側しか見ていなかった。

外側の見張りを外した。見張りは、売り物を出す頁それぞれに置く
（`tests/api-auth.mts` が頁を数えて、置き忘れを止める）。
**見張りは外側・内側の両方を見るようにした。**

これで、講座を開くときの往復は **10 → 1**。

## ③ どの画面からも呼ばれる `/api/me`

上から順に await していたので、聞く先の数だけ順番待ちしていた。
互いに要らないものは同時に聞く（`Promise.all`）。

**順番待ち 13回 → 5回。**

誰かを見る（`currentUser`）のは、前から1回だけ（`cache`）。
鍵が非対称なら手元で確かめて終わる（`getClaims`）。

## ④ 誰が見ても同じ画面は、作り置きにする

`/edu`（講座の一覧）は `force-dynamic` で、**押すたびにサーバで
組み立て直していた。**出るものは誰が見ても同じ（講座の名前・時間・根拠）で、
人によって違うのは札の「取得済」だけ。それは画面側があとから重ねている。

作り置きにした（1時間で入れ替わる。ホームと同じ）。

| 画面 | 前 | いま |
| --- | --- | --- |
| ホーム | 作り置き | 作り置き |
| 講座の一覧 | **押すたび** | 作り置き |
| マイページ | 作り置き | 作り置き |
| 講座の中身・単元・修了証など | 押すたび | 押すたび（受講コードを見るので、これでよい） |

`/edu/[courseId]/layout.tsx` の `force-dynamic` も外した。
見張る頁は、クッキーを読む時点で自動的にそうなる。
決め打ちにしていると、**見張りの要らない実技の手引きまで**毎回組み立て直す。

## 見張り

| 何を | どこで |
| --- | --- |
| 席と注文をひと息に聞いているか。会社の名前を先に聞いていないか | `npx tsx tests/api-shape.mts` |
| **送っている問い合わせの形**（1回で済んでいるか・講座で絞っているか） | `npx tsx tests/entitle-query.mts` |
| 外側・内側のレイアウトで見張っていないか（また手引きを塞がない） | `npx tsx tests/api-auth.mts` |
| 誰が見ても同じ画面が作り置きか。受講コードを見る画面が作り置きでないか | `npx tsx tests/api-shape.mts` |
| 押してから出るまでの時間 | `node tests/speed.mjs`（製品ビルドのサーバに当てる） |

`tests/entitle-query.mts` は、本物の supabase-js に組み立てさせて
**出ていく住所**を見る。手元に PostgREST が無いので、
「その形で送っている」ことまでを押さえる。
**その形を PostgREST がどう解釈するかは、本番で確かめる**（下）。

## ⑤ 2巡目（げんきさんの報告：2026-09-10 21:04）

> 受講コードを追加で申し込むがめちゃくちゃ遅い
> 請求書払いで申し込むもめちゃくちゃ遅い

### マイページと受講管理が、教材15MBを毎回読んでいた

`/api/mypage` は、こう書いていた。

```
for (const c of readyCourses()) {           // 73講座
  const lessons = await getLessonList(c.id); // 教材のJSONを開いて数える
```

欲しいのは**単元の数と学科の時間、2つの数字だけ**なのに、
台本も図も災害事例も確認問題も入った教材（合計15MB）を、
**73本、順番に開いていた。**手元で計って 272ms。
本番のサーバは冷えているので、もっとかかる。受講管理も同じことをしていた。

名前と分は動かない（教材を直したときだけ変わる）ので、
**先に数えて書き出す**ことにした（`npm run build:stats` →
`src/content/lessonStats.ts`。116KB）。

`getLessonList` がその表を返すので、**呼ぶ側は1行も直していない。**
中身が要るとき（単元を見る画面・修了証）は、これまでどおり
1講座ぶんだけ読む（`getCurriculum`）。

**272ms → 0ms。**

書き出したものが古いと、画面に嘘の数字が出る
（「13単元中12合格」が「12単元中12合格」になって修了に見える）。
`tests/lesson-stats.mts` が、いつでも教材と突き合わせる（299件）。

### 申込みの画面

`/api/order` も、互いに要らないものを上から順に待っていた（9回）。
注文・受講リクエスト・在籍者を同時に聞き、
そのあと人のぶんと注文のぶんを同時に聞く。**9回 → 3回。**

### 下部タブが固定されない（iPhone）

手元のブラウザでは、いちばん下まで送っても画面の下にぴたりと付いている
（`tests/nav-check.mjs`。ホーム・講座・申込み・マイページの4画面で確認）。
**再現できていない。**iOS の惰性スクロールでだけ、固定したものの
描き直しが後回しになって途中に取り残される症状に当たると思われる。

自分の層に切り出す手当てを入れた（`transform: translateZ(0)`）。
**固定した要素そのものに掛ける。**親に掛けると、`fixed` が親を基準に
してしまって、本当に固定が壊れる（見張りで止めている）。

これで直らなければ、次は作りを変える（画面を上下に分けて、
下の札を送らない場所に置く）。**ブラウザとホーム画面のアプリの
どちらで起きるか**、**送っている最中だけか、止めても戻らないか**を
教えてもらえると、そこを絞れる。
