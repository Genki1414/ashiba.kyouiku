# 第3章「火打とシート」の判定仕様

`HANDOFF.md` 3章の「現場のルール　第3章 火打とシート」を、そのままコードにしたものの対応表です。

| ファイル | 役割 |
|---|---|
| `src/training/ch3/layout.ts` | 割り付け（出隅4箇所・支柱6本・緊結ピッチ・結ぶ順） |
| `src/training/ch3/rules.ts` | 判定 |
| `src/training/ch3/state.ts` | 状態と進行 |
| `src/components/training/ch3/Parts.tsx` | 描画。プロトタイプから描画を変えずに移植 |
| `src/app/training/ch3/` | ゲーム画面 |

検査は2本あります。

- `npm run test:ch3` … 判定だけを直接叩く（60件）
- `npm run test:e2e:ch3` … 実際のブラウザで火打からシートまで通す

## 現場

4面が組み上がった状態を**平面図**で見ます。南面・北面＝3スパン、東面・西面＝2スパン。
シートを結ぶ段は**立面**に切り替わります。

## 火打

出隅4箇所（南東・南西・北西・北東）に掛けます。

| HANDOFF 3章 | 判定 | 分類（tag） |
|---|---|---|
| 支柱に付ける。基本的に手摺には付けない | 手摺を選ぶとファール。「どうしても手摺に付けるときは、その手摺に抜け止め措置をすること」 | 火打の取付先 |
| 出隅をまたいで両方の面に振り分ける | 同じ面の支柱どうしを選ぶとファール | 火打の掛け方 |
| 足場と**二等辺三角形**になるように掛ける | 出隅から違う距離の支柱を選ぶとファール | 火打の掛け方 |

目的は平面内でひし形に変形するのを防ぐこと。圧縮材と併用して引張効果が生じますが、
圧縮材は説明のみで操作はありません。

## シート

縦張り、1スパンに1枚、重ねしろ無し。

| HANDOFF 3章 | 判定 | 分類（tag） |
|---|---|---|
| まず全スパンを最上段から下へ垂らす | 3スパン垂らすまで次へ進まない | — |
| 広げるときは**足で挟む** | 足で挟まないとシートを落とす（−10）。落とすのがいちばん多い失敗 | シートを落とす |
| 緊結ピッチは450または900（戸建は900でよい） | 1,800を選ぶとファール | 緊結ピッチ |
| 支柱ごとの結束は**上から下**（4コマ目 → … → 1コマ目） | 順が違うとファール。900なら4コマ目・2コマ目 | 結ぶ順序 |
| 立っている踏板の高さ（0コマ）は候補に出すが選ぶとファール | 「踏板高さは下の段に立って結んだ方が効率が良い」 | 結ぶ位置 |
| **出隅は最後**。隣接する2本（南①・西①）を結んでから | 先に結ぶとファール。「隣の支柱の側に隙間が空く」 | 出隅を先に結んだ |
| 段単位。2段目の全支柱 → 1段目 → 地上 | ゲームでは2段目まで（以降は同じ繰り返しなので省略） | — |

## 判定の置き場所

プロトタイプの `SheetPart` は自前の判定を持っていましたが、**判定は `rules.ts` に一本化**し、
画面からは `act()` を通して渡すようにしました。同じルールが2箇所にあると必ずずれるためです。

火打も同じで、掛け方の可否は `checkHiuchi()` という純粋な関数にして、
画面（`HiuchiZoom`）と判定の両方から呼んでいます。

## プロトタイプとの差

- 音（SFX）は未移植。鳴らす場所だけ同じにしてあります
- ひし形変形のデモ（`Plan` の `skew`）は部品としては移植済みですが、画面には出していません
