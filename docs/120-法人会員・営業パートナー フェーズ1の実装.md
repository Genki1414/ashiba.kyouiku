## 出し方（指示書 §17）

**push しても本番は変わらない。** 入口は全部 `MEMBERSHIP_ENABLED=1` の店でだけ開く
（`src/lib/membership.server.ts`）。付けないあいだは、案内も申込みも運営の札も 404。
表（0040）は先に流してよい。使わなければ何も起きない。

開けるときにやること（げんきさんの承認のあと）：

1. Supabase の SQL Editor に `supabase/apply-all.sql` を流す（0040。足すだけ。消さない）
2. 利用規約・特商法の表記・業務委託契約書を、決めた条件で直す（下の「未決」）
3. Vercel の環境変数に `MEMBERSHIP_ENABLED=1` と `CRON_SECRET=（長い乱数）` を入れる
4. 変更履歴（`src/content/changelog.ts`）に載せる。**いまは載せていない**（載せると全員に更新の知らせが出る）
5. 本部の「会員と報酬」でプランの額を確かめる（seed は指示書どおり。画面で直せる）

## 流れ

```
担当者  /member でプランを選ぶ（紹介コードがあれば打つ／URL から来ればクッキーで入る）
   → contracts（pending）＋ 初月の contract_payments（pending）。運営に LINE
運営    /owner 会員と報酬 → 請求書を発行する → 相手に知らせる → 振込を確認 → 「入金を確認した」
   → pay_contract_payment：paid／契約 active／ロット付与（6か月。docs/121）／紹介元の報酬 confirmed／紹介元を固定
   → 担当者に「チケットが付きました」（お知らせ・LINE）
担当者  /order で講座と人数を選ぶ → 「チケットで払う」
   → spend_tickets（税抜。古いロットから。足りなければ SQL が止める）→ 注文 paid → 受講コード発行
毎朝    Cron：expire_tickets ＋ 次回が10日以内の契約に翌月の入金行 → 運営に「請求書を送ってください」
```

## 決めたこと

- **金額は全部 int（円・税抜）。** 税は出すときに floor(net × 10%) を1回。報酬は floor(net × 率 / 100)。
  式は `src/lib/membership.ts` と SQL に同じものがあり、`tests/members.ts` が突き合わせる
- **チケットは残高の列を持たない。** ロットごとに残額と失効日。増減は `ticket_txns` に全部残る。
  消費は行ロックの中で古いロットから。負にはならない（SQL が raise）
- **入金→有効→付与→報酬は SQL の1関数。** TS 側で `paid` やロットや報酬を手で書かない（`tests/members.ts` が見張る）
- **チケット払いの注文は売上に足さない。** 会費で先に入っているので、元帳・本部の売上では `method !== "ticket"` で外す。
  請求書も出ない（受講コードの注文の一覧では「チケット払い」と出る）
- **確定と見込みは別の数字。** 確定＝`commissions` の行（入金のあった分）。見込み＝有効な契約 × 率。足して1つにしない
- **紹介元は契約が立った時点で固定。** 変えられるのは運営だけで、理由を `referral_changes` に残す。自分のコードで自分の会社は紹介できない
- **振込先は本人と運営だけ。** `/api/partner` と `/api/owner/members` 以外から `partner_bank` を返さない
- **月は日本の日付で切る。** `monthStart()`。世界標準時のまま切ると月初の朝9時前がひと月前になる
- 月額の払い方は**請求書払い（運営の入金確認）だけ**。カードの自動引落（Stripe Billing）は後ろへ（docs/119 §9）
- 販売代理店は `kind='agency'` の契約として同じ道で動く（チケット200%）。協力会社への配布と代理店ショップはフェーズ2。
  案内（/agency）にも「準備中」と書いた
- 運営の操作は `admin_logs` に残す（誰が・何を・前後）

## 両店の Cron

`vercel.json` は両店で同じなので、Cron は足場屋革命と特別教育ドットコムの両方で毎朝動く。
データベースは1つ。`open_contract_payment` は月で一意、失効は残額 0 を見るので、2回動いても二度は起きない。
運営への LINE は「新しく起こした件数」で送るので、2店目は 0 件になり鳴らない。
