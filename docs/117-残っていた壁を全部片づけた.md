読み取りの失敗を受け取っていなかったので、データベースが一時的に断っただけで
**本物の修了証に「その番号は存在しません」と返していた。**誤答の向きが最悪。

読めなかったら 503 で「いま照会できません」と言う。掛け直せば通る。
氏名（伏せ字）は添え物なので、そこが読めなくても番号の照会は返す。

## 開発用の逃げ道を、本番で塞いだ

**「＋1分（開発用）」の札**が、本番でもログイン切れやサーバの一時的な失敗で
出ていた（`mode === "local"` で出していた）。サーバは実経過で頭打ちにするので
記録の水増しにはならないが、受講者に見える。`NODE_ENV` で本番では消す。

**確認問題**が、通信不調のとき端末内で合格になっていた。修了証はサーバの記録を
見るので「合格したのに修了証が出ない」に行き着く。本番では端末内の判定をやめ、
「合格を記録できませんでした」「ログインが切れています」とその場で言う。

## 消費税の端数を、1請求書につき1回にした

インボイス制度では、端数処理は**1つの適格請求書につき税率ごとに1回。**
行ごとに切っていた。500円刻みの単価では出ないが、パーセント型のクーポンで1円ずれる。

```
足場4,500＋石綿4,500 に 7%引き → 315／315
行ごと：net 4,185 → floor(418.5)=418 ×2 = 836
1回で：net 8,370 → floor(837.0)   = 837
```

税額を先に1回で決めて、行に配る（`groupAmounts`）。端数の1円は高い行が背負う。
請求書は税込から割り戻すのをやめ、単価×人数から税抜を出す。
「10%対象」の行も足した（税率ごとに区分した対価の額）。
