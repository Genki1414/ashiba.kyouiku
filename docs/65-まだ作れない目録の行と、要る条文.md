## 5. なぜ、検索結果で作らないのか

**docs/19 の④と、docs/24 の決めごとがあるからです。**

> 条文で確かめた条番号だけ書く。
> よその講習の頁で目録を直さない。条文が出るまで直さない。

そして、実際に一度やらかしています（**docs/53 の訂正**）。
隣の教育を「規程第12条」と書いていて、**第12条はローラーでした。**
げんきさんが「条文探して正確に進めてね」と言ってくれて、条文を見て直しました。

**検索で出てくるのは、講習会社の頁と、要約です。**
**科目の名前が一つ違うだけで、目録に出る時間が変わり、修了証の紙が変わります。**
**そこは、条文が来るまで待ちます。**

いま3章で規程の名前と告示番号だけ入れたのは、
**「安全衛生特別教育規程」という明かに違う名前が入っていたのを、直すため**です。
名前と番号は、厚生労働省の告示ページの見出しに書いてあったものです。
**それでも「条文未確認」の印は付けたままにしてあります。**

## 6. できたら、この順で作ります

条文が届いたら、いままでと同じやり方です。

1. 条文の表から、科目・範囲・時間をそのまま写す（解説文は写さない）
2. 中欄の項目の数だけ単元を作る
3. 実技があれば `gate: "drill"`。手引き（うちの案）と実施記録の様式を付ける
4. 例は全業種から散らす。**足場屋の例は入れない**
5. 確かめた条番号だけ書く。残りは中身だけ教えて、docs に残す
6. tsc → 30本のテスト → drill.sql → admindb → e2e 3本 → 実技の画面を見る → next build
7. docs を書いて、commit して、push して、Supabase 用の SQL を送る
