# 118　ひとりで受けると、無料の1単元

2026-09-17。げんきさん

> 利用者が増えない
> 会社登録が邪魔してる気がする
> 1と3作って

## 何が起きていたか

投稿を見て来る人は1人。ところが受講コードは会社しか買えなかった（0018）。
学科を開くまでに、この7段があった。

1. ログイン
2. /join で会社を登録し、自分を教育担当者にする
3. /order で人数と宛名を入れて申し込む
4. 請求書を見て銀行振込
5. 運営が入金を確認する
6. 受講コードが出る。自分に配って、自分で引き換える
7. 学科が開く

会社の話が出た時点で「うちの話じゃない」と閉じる。しかも払う前に中身を1単元も
見られないので、先に振り込む理由が無かった。

## 1　ひとりで受ける（0039）

会社を作らない。担当者も名簿も無い。**講座を選ぶ → 払う → 受ける**の3つ。

| これまで | いま |
| --- | --- |
| 会社を登録して担当者になる | 要らない |
| 人数ぶん申し込む | 1名分だけ（/solo） |
| 受講コードを配って引き換える | 入金を確認した瞬間に、本人の席が立つ |

### データの形

実務トレーニングの個人注文（0018）と同じ形を使う。`orders.user_id` に本人、
`kind='seat'`、`company_id` は空。0018 の「席は会社しか買えない」（orders_seat_is_company）
を外した。「会社か個人かどちらか片方」（orders_owner_one）は変えていない。

### 入金＝席＝受講の記録を、1つの関数で

`pay_solo_seat(p_order)`。入金を立て、本人の席を1つ立て（used_by 本人）、その講座の受講の
記録に紐づける。3つに分けると「払ったのに開かない」「開いているのに未入金」が起きる。

二度呼んでも席は増えない（Stripe の知らせは二度来る）。運営の「入金を確認した」と、
Stripe の知らせの両方から呼ぶ。

受講の門番（席→注文→講座）はそのまま通る。修了証の門番（席→注文→入金済み）もそのまま通る。
**会社が無くても修了証は出る**（運営の名義。今までどおり）。

### クーポン

使える。`use_coupon` に会社は渡さず、個人の利用として記録する。広告費の計算は同じ。
クーポンの確かめ（/api/coupon）は、担当者だけでなくログインした人なら使えるようにした。

### カード

鍵（STRIPE_SECRET_KEY）が入っている店だけ札を出す。checkout は申し込んだ本人も始められる。
戻り先は /solo。いまは鍵が無いので請求書払いだけ。

### 入口

- ホーム：「ひとりで受ける」を「会社とつなぐ」より先に
- /join：いちばん上に「ひとりで受ける」
- 断りの画面（受講コードが必要です）：「ひとりで受ける」を受講リクエストより先に
- 道のり（はじめかた）：2段目を「受け方を選ぶ」に

会社で受ける道は、どこも消していない。

## 3　無料の1単元

`/edu/<講座>/try`。**ログインなし・第1単元だけ・記録なし。**

本番の受講画面と同じ部品で同じ順に進む（解説→図解→事例→確認問題）。違うのは3つだけ。
時間を数えない・合格を記録しない（/api/progress を呼ばない）、顔の照合をしない、
受講の準備へ送らない。終わったら「ひとりで受ける」「会社で受ける」へ。

開けるのは try の1段だけ（正規表現）。`/edu/<講座>`（目次）と `/edu/<講座>/<単元>`（本番）は
閉じたまま。講座を選ぶ入口 `/try` も開けた。ログイン画面から「登録の前に見てみる」で来る。

  入金後は修了証が出る／実務トレーニングの注文には使えない。何度でも流せる

## やらなかったこと・別に足したこと

- （同日に足した）本部の元帳に「個人（会社を通さない申込み）」の欄。会社を通さずに
  受けた人の記録は、どの事業者の元帳にも出なかった。一覧のいちばん上に置き、
  受講した人・修了証・売上は全体の数字にも足す。3年経過分を消す画面は前から
  人ごとの作りなので、そのまま個人も出る
- カード払いは鍵を入れれば動く作りだが、実際の決済は通していない
- 本番の目次（/edu/<講座>）をログインなしで見せることはしていない
