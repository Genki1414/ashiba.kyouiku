# 受講コードを指して配る、取得済には配らない（0031）

2026-09-09。げんきさんの依頼が2つ。

- 「担当者の受講コード画面からコードを配れるようにしたい。受け取った側にも通知表示。コードを使うボタン→コード入力せず受講可能とする」→「1だね」（通知を押すと講座がそのまま開く）
- 「取得済みの資格は講座一覧にも取得済表示。取得済の資格には受講コード配布不可」

## 指して配る

0028 の `assign_seat` は空いている席から自動で1枚選んでいた。受講コードの一覧には
コードが1枚ずつ並んでいるので、そこに「配る」を置くなら**押したそのコード**が
渡らないとおかしい（「EQ37 で配ったのに相手には EPB7」だと口頭で確かめられない）。

- `assign_seat(p_company, p_user, p_course, p_admin, p_code default null)`。指せばその1枚、指さなければ今までどおり自動。古い4引数は drop してから作り直す（同名が2本並ばない）
- 指したコードが配れない理由は4つ（よその会社・別の講座・使用済み・期限切れ）あるが、**どれかは言わない。**よその会社のコードを打って「別の講座です」と返すと、そのコードが在ることを教えてしまう
- `/api/admin/assign` は `code` を任意で受け、`normalizeJoinCode` で揃えてから渡す。渡ったら本人に `given` の知らせ。知らせの行き先は `/edu/<course>`（コードは打たない）
- 画面：`/order` の受講コード一覧、未使用の札に「配る」→在籍者を選ぶ→「この人に配る」。在籍者は `/api/order` GET が `members` で返す（承認済み・辞めていない人だけ）

## 取得済には配らない

「取得済み」は2通り。この仕組みで修了証が出ている（`certificates`、取り消し除く）と、
本人がマイページで入れた「取得済みの資格」（`held_quals`、`src/content/quals.ts` の
`courseId` で講座に当たるもの）。名簿の「取得済み資格」と同じ数え方。

数える所は1か所 `src/lib/held.ts`（`heldCourseIds`）。見る所は3つ。

| 所 | やること |
|---|---|
| `/api/me` → `HeldMark` | 講座の札（`CourseCard`）に「取得済」。ホームも `/edu` も同じ札。作り置きの一覧に人の情報は載せず、札が後から /api/me に1本で聞いて付ける |
| `/api/order` → 配る相手 | `members[].held`。取得済みの人は名前は出すが押せない（外すと「あの人が居ない」になる） |
| `/api/admin/assign` | 画面をすり抜けても 409 で断る。名簿の「席を配る」も `r.held` を見て出さない |

SQL 側（`assign_seat`）も修了証を見る。席を戻した（`release_seat`）あとは
`enrollments.seat_id` が空に戻るので「もう渡っている」では止まらない。
修了証そのものを見る必要がある。取り消した修了証なら渡る（受け直しの道は残す）。
