# 講座マスター（訂正版）で目録を直した記録

直した日：2026年9月5日
直した先：`src/content/tokubetsu.ts`（目録）／`tests/tokubetsu.ts`（見張り）

---

## 1. 決めたこと（これが今後の順番）

**法定教育時間は、次の順で決める。**

| 順 | 何 |
|---|---|
| 1 | **現行の労働安全衛生関係省令**（安衛則、クレーン則、電離則、高気圧作業安全衛生規則…） |
| 2 | **省令から委任された現行の告示**（○○特別教育規程） |
| 3 | 厚生労働省・労働局などの**公式のまとめ** |

**民間サイトの一覧表は、法定時間の根拠にしない。**

うちの目録は、もともと 3（労働局のまとめ）が出どころだった。
1・2 と食い違ったら、**1・2 を採る。**
ただし**うちがまだ告示の全文を見ていないうちは、`checked` を付けない。**
（外に出る通信が組織の決まりで止まっていて、e-Gov も厚生労働省も開けない。docs/65）

## 2. 目録に足した項目

げんきさんの「各講座マスターには最低でも以下を保持する」に合わせて、
`Tokubetsu` に次を足した。

| 足した項目 | 何 |
|---|---|
| `gakka` | **学科の科目と、科目ごとの法定最低時間（分）** |
| `jitsugi` | **実技の科目と、科目ごとの法定最低時間（分）** |
| `variants` | **業務区分。**ここが入っている行を、一つの固定時間で実装しない |
| `fromMaster` | 時間の出どころが講座マスター（2026年9月5日）である印 |
| `checkedOn` | **法令を確かめた日** |

時間は**すべて「分」で持っている。**時間・分への直しは表示のときだけ
（`hoursText`）。これは前からそうしてある。

**見張り（tests/tokubetsu.ts）も足した。**

- **学科の科目の合計 ＝ 学科の法定時間**（ずれたら落ちる）
- **実技の科目の合計 ＝ 実技の法定時間**
- 実技がある行は、実技の科目も書いてある
- **業務区分を持つ行は、講座にしていない**（一律の時間で修了証を出さないため）
- **業務区分を持つ行に `checked` を付けない**
- 高圧室内は420分・実技0（前の版の540分＋180分を使っていない）
- 除染等業務は通常区分で240分＋90分、かつ業務区分を持っている

## 4. 修了証に、出したときの中身を焼き付けた（同じ日にやった）

げんきさんの設計ルールにあった、

> 法令改正時に既存修了者の履歴まで書き換わらないように、
> 講座マスターには法令バージョンを持たせる。
> 修了時点の講座名・科目・法定時間・根拠法令・根拠告示・法令バージョンを
> enrollment/certificate 側へスナップショット保存すること。

これを入れた。**migrations/0026_cert_snapshot.sql。**

### 何が問題だったか

`certificates` は「誰の受講か」と「番号」と「出した日」しか持っていなかった。
**紙に載る講座名・科目・法定時間・根拠は、見るたびに `courses.ts` の
そのときの値から作っていた。**

つまり**法令が変わって講座を直した日に、前に出した修了証の中身まで変わる。**
3年保存している記録が、あとから書き換わるということ。記録として成り立たない。

### 直したこと

`certificates` に足した欄。

| 欄 | 何 |
|---|---|
| `course_id` | どの講座か（参照は張らない。講座を消しても紙は残る） |
| `course_name` | **出したときの正式名称** |
| `basis` | **出したときの法令の根拠** |
| `total_min` | **出したときの法定時間（分）** |
| `subjects` | **出したときの科目と時間**（jsonb） |
| `law_version` | **出したときの法令バージョン** |

**法令バージョン**は `src/content/courses.ts` の `LAW_VERSION`（いまは `2026-09-05`）。
講座ごとに `lawVersion` を書けば、その講座だけ別の版にできる。
**法令が変わって講座の科目・時間・根拠を直したら、その講座の版を上げる。**

書き込むのは**発行の瞬間**。受講者が自分で出したとき（`/api/cert`）も、
担当者が出したとき（`/api/admin/cert`）も、同じものを書く。
読むときは**焼き付いた値を先に使う。**教材の側は見ない。

0026 より前に出した紙はこの欄が空。**そのときだけ今の教材で補い、
画面に断りを出す。**

### ついでに見つかった、もっと悪いもの

**修了証の照会（`/verify`）が、どの証明番号を入れても
「足場の組立て等の業務に係る特別教育（学科）」と答えていた。**

講座が1つだった頃の書き方が、そのまま残っていた。
**玉掛けの修了証を照会した元請けに、足場の名前を見せていたということ。**
出した紙に焼き付いた講座名を返すように直した。
名前の残っていない古い紙は、**当てずっぽうの名前を出さずに、
「お手元の紙で確かめてください」と出す。**

### 見張り（tests/cert.ts）

- 0026 が6つの欄を足している／apply-all.sql にも入っている
- **発行のときに、講座名・科目・法定時間・法令バージョンを書き込んでいる**
- **担当者の発行も、同じものを書き込んでいる**（片方だけだと担当者の紙に残らない）
- **もう出してある紙は、出したときの値を返している**
- **照会が、どの番号にも「足場」と答えない**
- 古い紙は、当てずっぽうの名前を出さずに断る
- 法令バージョンが、全部の講座で日付の形で引ける

**本番の Supabase に 0026 を流すこと。**（0025 もまだなら、先にそちらを）

## 5. 直していないもの

**時間を直したのは、講座マスターに数字が書いてあった行だけ。**
書いていない行は触っていない（docs/24 の決まり：条文が出るまで直さない）。
