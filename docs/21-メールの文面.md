# 認証メールの文面と差出人

## なぜ直すか

合言葉の決め直しのメールが、こう届いていた。

```
差出人  Supabase Auth <noreply@mail.app.supabase.io>
件名    Reset your password
本文    We received a request to reset your password. …
```

**現場の人が受け取って、まず詐欺メールを疑う。**
知らない英語の差出人から、英語で「パスワードを再設定しろ」とリンクが来る。
迷惑メールの見分け方として教わるものと、そっくり同じ形をしている。

押してもらえなければ、合言葉を忘れた人はそこで詰まる。
教育担当者に連絡してもらうことになるが、
**その担当者本人が忘れたときは頼む相手が居ない**（docs/07）。

直す所は2つあり、手間も効き目も違う。

| | 直せるもの | 要るもの |
| --- | --- | --- |
| **文面** | 件名・本文・差出人の**表示名** | Supabase の画面だけ。無料 |
| **差出人の住所** | `noreply@mail.app.supabase.io` そのもの | 自前の SMTP |

## 文面（先にこちらをやる）

**Authentication → Emails → Templates** で、テンプレートごとに件名と本文を差し替える。

使っているのは次の2つ。ほかは触らなくてよい。

| テンプレート | いつ飛ぶか |
| --- | --- |
| **Reset Password** | ログイン画面の「合言葉を忘れた」 |
| **Confirm signup** | `Confirm email` を ON にしているときの登録 |

`{{ .ConfirmationURL }}` は Supabase が本物のリンクに差し替える。**消さないこと。**

### 決めたこと

- **名乗る。** 「足場屋革命（東北三上機材株式会社）」と、所在地・電話まで入れる。
  差出人の住所が supabase.io のままである以上、
  **本文で誰から来たのかが分からないと、詐欺メールと区別がつかない。**
- **「パスワード」と併記する。** 画面では「合言葉」で通しているが、
  メールは受信箱で他の通知と並ぶ。そこだけ独自の言い方だと、何のメールか分からない。
- **心当たりが無いときにどうすればいいかを書く。**
  「無視してよい」だけでなく「合言葉は変わらない」まで書く。
  変わってしまうと思って慌てて押す人が出る。
- **リンクの期限に触れる。** 切れたときに「壊れた」と思わせない。

## 差出人の住所（自前の SMTP）

**Authentication → Emails → SMTP Settings** で「Enable Custom SMTP」を入れる。
Supabase の画面にも「本番向けではない」と警告が出ている。

**見た目の話だけではない。**

- **標準の送信は1時間に数通しか出ない。**
  講習の当日に何人かが同時に「合言葉を忘れた」を押すと、
  **途中から黙って届かなくなる。** 画面は「送りました」と出したままになる。
- **迷惑メールに入りやすい。** supabase.io は大勢が共用している送信元で、
  こちらでは何も手を打てない。
- **返信できる住所になる。** いまは `noreply@`。困った人が返信しても誰も読まない。

### どのドメインから出すか

**`ashibase.jp` から出す。`tohoku-mikamikizai.co.jp` は使わない。**

会社のドメインには、いま現に会社のメールが流れている。
そこに送信の設定（SPF）を足すのは危ない。

> **SPF レコードは、1つのドメインに1本しか置けない。**
> すでにある所へ2本目を足すと、規格違反（permerror）になり、
> **会社のメールが丸ごと届かなくなることがある。**
> 足すなら既存の1本に書き足すことになるが、
> 書き間違えれば同じことが起きる。

`ashibase.jp` は取ったばかりで、メールを1通も流していない。
壊れるものが無いので、失敗しても会社の業務に響かない。

**受け取る側にとっても、そのほうが自然。**
`kyouiku.ashibase.jp` を開いている人に `ashibase.jp` から届く。
別のドメインから届くより、つながりが分かる。

差出人は `noreply@ashibase.jp` のような住所にする。
特商法に載せた `info@tohoku-mikamikizai.co.jp` と違ってよい。
あちらは**人が書く先**、こちらは**仕組みが出す先**で、役割が別。

### 手順

1. **送信の業者を決める**（Resend・SendGrid・Amazon SES・Brevo など）。
   料金と無料枠は変わるので、そのとき確かめること
2. **業者の画面で `ashibase.jp` を登録する。**
   DKIM と SPF の DNS レコードを出してくるので、
   **お名前.com の「DNSレコード設定」にそのまま足す**（ドメインを取った所と同じ画面）。
   `kyouiku` の CNAME はそのままでよい。メールと Web のレコードは同居できる

   **Resend の場合**
   - リージョンは **Tokyo (ap-northeast-1)**。あとから変えるには
     ドメインを消して登録し直すことになる
   - **クリック追跡（click tracking）は切る。** 既定で入っている。
     入れるとメールの中のリンクが追跡用の URL に書き換えられ、
     **1回きりの鍵が途中で使われて、リンクが壊れることがある**
     （Resend 自身が「verification link を壊すことが知られている」と書いている）。
     せっかく差出人を自社ドメインにしても、リンク先が別のドメインでは
     詐欺メールに見えるという問題もある
   - 追加フォームでは切れない。**ドメインを作ったあと、
     そのドメインの画面のいちばん下**で切る。
     **Supabase の SMTP に繋ぐ前に切ること。**
     切る前に送らなければ、追跡付きの認証メールは1通も出ない
3. 業者の画面で「認証できた」と出るまで待つ。DNS の反映に時間がかかる
4. **Supabase → Authentication → Emails → SMTP Settings**

   | 欄 | 入れるもの |
   | --- | --- |
   | Sender email | `noreply@ashibase.jp` |
   | Sender name | `足場屋革命` |
   | Host / Port | 業者が出すもの。**Port は 587**（STARTTLS） |
   | Username | 業者が出すもの |
   | Password | 業者が出す鍵。**チャットに貼らない** |

   **Sender email と Username を一致させること。**
   食い違うと、送信元のなりすましとみなして弾く業者が多い。

5. **Authentication → Rate Limits で上限を上げる。**
   自前の SMTP にしても上限は消えない。既定は1時間に30通で、
   そこから手で上げる。**ここを忘れると、業者を入れた意味が半分になる**
6. `src/content/authMail.ts` の `AUTH_MAIL_FROM` を空文字にする。
   画面に出している「差出人は Supabase Auth です」の案内が消える。
   **直し忘れると、嘘の差出人が出たままになる**（/setup にも出している）

### 入れたら必ず1通試す

送信元を変えると、Redirect URLs と違って**画面には何も出ないまま届かなくなる**。
自分宛てに1通送って、受信箱に着くところまで見ること。
迷惑メールに入っていないかも見る。

## 確かめ方

1. ログイン画面 →「合言葉を忘れた」→ 自分のメール
2. **受信箱の一覧で**、差出人と件名が日本語で読めるか
3. 迷惑メールに入っていないか
4. ボタンを押して `kyouiku.ashibase.jp/login/new` へ着くか
