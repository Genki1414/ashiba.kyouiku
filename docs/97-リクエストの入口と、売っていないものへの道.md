# 97　受講リクエストの入口と、売っていないものへの道（2026-09-08）

げんきさんの「特別教育ドットコムの方にリクエスト周りが実装されてない」。

調べたら、**仕組みは両方の店で同じコードが動いていた。**
足りていなかったのは入口で、そのついでに、
**売っていないものが開ける道**が3本残っているのが見つかった。

---

## 1　まず確かめたこと：仕組みは同じだった

店で分かれているファイルは、これだけ（`grep BRAND`）。

    layout.tsx / page.tsx / edu/page.tsx / manifest.ts
    legal/terms / legal/privacy / authMail.ts / courses.ts(SERVICE_NAME) / notifyText.ts

受講リクエストに関わるものは、**1つも入っていない。**

| 見たもの | 店で分かれているか |
| --- | --- |
| `src/app/api/course-request/route.ts`（送る口） | 分かれていない |
| `src/app/join/JoinClient.tsx` ④（送る画面） | 分かれていない |
| `src/components/HomeCards.tsx`（入口の札） | 分かれていない |
| `src/app/admin/AdminClient.tsx`（担当者が受け取る所） | 分かれていない |
| `src/components/OtherCourses.tsx`（講座の一覧・探す窓） | 分かれていない |

Vercel の `tokubetsu-kyouiku` も、いちばん新しい commit で配信できていた。
**「特別教育ドットコムにだけ無い」ものは、無かった。**

## 2　では何が足りなかったか：入口が1つで、しかも遠かった

送る所は `/join` の④にある。そこへ行く案内は、**ホームの札1枚だけ**だった。

    HomeCards … me.canLearn && me.member === "active" && !me.admin

つまり**席を持っている人にしか出ない。**

- **まだ席が1つも無い人**には、入口がどこにも無い
- **教育担当者**にも出ない（自分に頼むことになるので、これは正しい）

そして、いちばん「受けたい」と思うのは、
**講座を押して「受講コードが要ります」と断られた瞬間**（`NeedSeat`）。
その画面に出ていたのは3つで、送る所は無かった。

    受講コードを入れる → /join
    教育担当者の方はこちら（申込み） → /admin
    実務トレーニングの第1章は、コード無しで遊べます → /training

`/join` へ行けば送れるが、そこで**73講座の中からさっき見ていた講座を
探し直す**ことになる。平らに73本並べる店（特別教育ドットコム）では特にきつい。

### 直したもの

`src/components/RequestCourse.tsx`（新）を `NeedSeat` に置いた。

- どの講座かは**住所から取る**（`/edu/<courseId>/…`）。
  見張りはレイアウト（`src/app/edu/layout.tsx`）なので courseId を受け取れない
- 在籍していない人には、釦の代わりに「先に会社とつないでください」
- もう送ってある講座には「送ってあります」。二重に送れない
- **席そのものはここで作らない。**叩く口は `/api/course-request` の1本だけ
  （`tests/brand.ts` が数える）。作れると、金額を見ないまま売り物が出る

## 3　ついでに見つかった：売っていないものが開けた

特別教育ドットコムは実務トレーニングを売っていない。
2026-09-07 に**利用規約と個人情報の取扱いからは外した**（docs/93、お知らせ 182）。
ところが**画面と道はそのままだった。**

| 残っていた道 | 何が起きるか |
| --- | --- |
| `NeedSeat` の「実務トレーニングの第1章は…」 | 売っていない店で勧めていた |
| `/training`（章の一覧・第1章・カタログ・見学） | 住所を打てば開いた |
| `/train`（**申し込み**。第2章から先は有料） | 住所を打てば開いた |
| `/updates` の「章の一覧へ」 | 行き先が無い札 |
| お知らせの `train`（実務トレーニングが開きました） | DB は両方の店で同じ。行き先が無い |

**規約が対象にしていないものを、有料で売れる状態だった。**

札を消すだけでは足りない（住所を打てば開ける）ので、**道ごと 404 にした。**

    src/app/training/layout.tsx   if (!BRAND.training) notFound();   ← /training/* 全部
    src/app/train/page.tsx        if (!BRAND.training) notFound();   ← 申し込み

お知らせは、一覧からも**数える方からも**外した
（`src/app/api/notices/route.ts`）。一覧から消して数だけ残すと、
「1件」と出ているのに開くと何も無い、という出方になる。

## 4　試験

`tests/brand.ts` に足したもの。

- 断られた画面に送る所があるか。**見ていた講座を持って送っているか**
- 席を作れないこと（叩く口が受講リクエストの1本だけか）
- 在籍していない人に、次にやることを出しているか
- この入口を店で分けていないこと（ホームの札と同じ考え方）
- `/training` と `/train` が、売っていない店で `notFound()` になるか
- `/training` への行き先を持つファイルが、`BRAND.training` で分けているか
- お知らせを一覧と数の**両方**から外しているか

`tests/api-shape.mts` に、断られた画面が API の返す項目
（`courseId` / `requested` / `hasSeat` / `member.state`）を読んでいるかを足した。
型では捕まらない（fetch の戻りは any）。

### 売り物の名前で待っていた試験を直した

`e2e-order` と `e2e-admin` は、ホームが描き終わるのを
`waitForSelector("text=実務トレーニング")` で待っていた。
**売り物の名前で待つと、店を増やしたときに関係のない試験が止まる。**
どちらの店にも必ず出る講座の札で待つように直した。

    '[data-testid="home-course"], [data-testid="course-drawer"]'

`e2e-catalog-demo` は実務トレーニングそのものの試験なので、
**売っていない店では「無いこと」を確かめて終わる**ようにした
（`/training`・`/training/catalog`・`/training/ch1`・`/train` が 404）。
素通りさせると、開けるようになっても気づけない。
