# 事業者・参加コード・教育担当者の画面

この教材は**外販**します。同じ画面をいくつもの会社が使うので、
「誰がどの会社の人か」＝**事業者**で分けます。
これは名簿と参加コードの話です。

> **修了証の名義とは別です。** 修了証は
> 「東北三上機材株式会社／中川元基」で決まっています（docs/08）。
> 特別教育を実施したのが東北三上機材だからです。

---

## 1. 仕組み

```
事業者（会社）
 ├ 教育担当者（admin）… 名簿を見る／修了証を出す
 └ 受講者（learner）　… 学科と実務トレーニングをやる
```

- 登録しただけの人は、**どこの事業者にも属していません**
- 属し方は2つ
  - **参加コード**を入れる … すでにある会社に入る（受講する人）
  - **事業者を作る** … 自分の会社で使い始める（＝最初の教育担当者になる）
- 見えるのは**自社だけ**。画面の出し分けではなく、
  サーバ（`/api/admin/*`）とデータベースの行レベルセキュリティの両方で止めています

---

## 2. 会社が使い始めるとき

1. 教育担当者になる人が登録・ログインする
2. `/admin` を開く → 「事業者を作る」が出る
3. **事業者名**を入れて「この事業者で始める」

事業者名は**名簿を分けるため**のものです。修了証には出ません。

作ると同時に、**参加コード**（8文字）が1つできます。

---

## 3. 受講者を入れる

`/admin` に出ている参加コードを、受講する人に渡します。

受講する人は、登録・ログインしたあと `/join` でコードを入れます。
ホームにも「参加コードを入れる」が出ます。

- 8文字。**0・1・O・I・L は使いません**（紙に書いて渡すので読み違えないように）
- 小文字で入れても構いません
- 漏れたら `/admin` の「参加コードを作り直す」で新しくできます。
  **前のコードは使えなくなります**（すでに入っている人はそのまま）

> 2人目以降の教育担当者は、一覧の「この人を教育担当者にする」で増やせます。
> 担当者が1人しか居ないときは、その人を降ろせません（誰も開けなくなるので）。

---

## 4. 画面の見かた

上に4つの数字。

| | 意味 |
|---|---|
| 受講者 | 自社に属している人 |
| 学科修了 | 全13単元と修了試験に合格した人 |
| 修了証 | すでに修了証を出した人 |
| **未発行** | 出せるのに、まだ出していない人 ← **担当者がやることはここ** |

一覧は **未発行の人が上** に来ます。

1人ぶんの中身：

- **学科** … 単元の数だけでは進み具合が分からないので、4つ出します
  - 合格した単元 / 全13単元 と、その割合のバー
  - **見た時間 / 法定の合計**（6時間）。法定時間に届いているかはこれで見ます
  - **いま受けている単元**（見た時間が入っていれば「いま 1-4 …（10分/30分）」、
    まだなら「次は 1-1 …」）。全部終わっていれば「全単元を終えています」
  - 単元は**受かっていない いちばん前のもの**を「いま」とします
- **修了試験** … 点数と合否
- **実務** … 第1〜3章の **本番の最高技能点**。80点以上が緑。
  チュートリアルは数えません
- **修了証** … 証明番号と発行日。まだなら「修了証を発行する」

---

## 5. 修了証

- 名義は「東北三上機材株式会社／中川元基」で決まっています（docs/08）
- 出せる条件は本人が出すときと同じで、**全13単元の合格＋修了試験の合格**。
  画面から頼まれても、条件を満たしていなければサーバが断ります
- 証明番号は**データベースで採る通し番号**（`AT-西暦月-通し番号`）。
  会社をまたいでぶつかりません
- 間違えて出したら「取り消す」。行は消えず、取り消した印が付きます。
  取り消したあとは出し直せます（番号は新しくなります）

## 6. 実務トレーニングの成績

- **端末** … 章の一覧の成績と間違いノートはこちら。圏外でも動きます
- **サーバ** … 教育担当者が見るのはこちら

1章通し終えるたびに両方へ1件ずつ。送れなくても端末の記録は残ります。
合否（80点）は**サーバでもう一度計算**します。端末の言い分では決めません。

---

## 7. 外販するときに、やってはいけないこと

| | なぜ |
|---|---|
| `DEV_ENROLLMENT_ID` を設定する | ログインしていない人の記録が1か所に混ざります。手元で試すときだけ |
| `SUPABASE_SERVICE_ROLE_KEY` に `NEXT_PUBLIC_` を付ける | 鍵がブラウザに出ます。RLS を全部飛び越えられます |
| `anon public` 鍵を Sensitive にする | `NEXT_PUBLIC_*` の埋め込みが止まり、ログインが動かなくなります |
