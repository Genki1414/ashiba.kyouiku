## 2. データモデル → Supabase マイグレーション

`supabase/migrations/` に3本置きました。PostgreSQL 16 に実際に適用して、
構文と業務ルールの両方が通ることを確認済みです（手順は `supabase/tests/README.md`）。

| ファイル | 中身 |
|---|---|
| `0001_init.sql` | `SPEC.md` 第3章の9表。列挙型・制約・索引 |
| `0002_rls.sql` | 行レベルセキュリティ。受講者は自分の行、担当者は自社の行 |
| `0003_rules.sql` | `SPEC.md` 第5章の決まりを DB 側で担保する関数とトリガ |

**SPEC からそのまま起こしたところ**

- 表・列・列挙値は `SPEC.md` 第3章のとおりです。`users.id` は `auth.users.id` と同一にしました。
- `verify_logs` は結果と理由だけで、画像も特徴量も列を持ちません。

**判断して足したところ（確認をお願いします）**

1. **`lessons` 表を1つ足しました**（`0003`）。単元ID・科目ID・題名・`legal_min` だけの参照表です。
   規定時間に達したかの判定を、クライアントの申告に任せないためです。
   `scripts/sync-lessons.ts` で `curriculum.json` から写します。教材本体は DB に入れません。
   （`legal_min` は科目の合計と単元の合計が一致していることを確認しました。1章180／2章30／3章90／4章60＝360分）
2. **視聴時間は `sync_watched_sec()` 経由だけ**にしました。`progress` に更新ポリシーを置いていないので、
   クライアントから直接は書けません。送られた秒数は「前回同期からの実経過＋2秒」で頭打ちにします。
   `SPEC.md` 5章の「クライアントの時刻は信用しない」をこの形にしました。
3. **確認問題の合格は `mark_quiz_passed()` 経由だけ**にしました。`lessons.legal_min × 60` 秒に
   達していなければ例外を返します。
4. **修了証は未入金だと入りません**。`certificates` への挿入時に、受講コード → 注文をたどって
   `status = 'paid'` を確かめるトリガを入れました。請求書払いでも受講コードは即時発行できます。
5. `orders` に `status='paid'` と `paid_at` の整合を強制する検査制約を入れました。

**確認した動き**（`supabase/tests/rules.sql`。8件すべて意図どおり）

| # | 確かめたこと | 結果 |
|---|---|---|
| 1 | 1,000秒と申告しても実経過ぶんしか入らない | 2秒だけ加算 |
| 2 | 規定時間未満で合格にしようとする | 「規定時間に達していません（2秒 / 3000秒）」 |
| 3 | 規定時間到達後に合格する | 通る |
| 4 | 未入金で修了証を発行する | 「未入金の注文です。修了証は発行できません」 |
| 5 | 入金後に発行する | 通る |
| 6 | 他人の受講の視聴時間を加算する | 「受講者が一致しません」 |
| 7 | 受講者が自分を admin に書き換える | 「所属と権限は変更できません」 |
| 8 | `status='pending'` のまま `paid_at` を残す | 検査制約で拒否 |
