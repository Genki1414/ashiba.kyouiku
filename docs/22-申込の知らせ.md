# 申込が来たことを、LINE で知らせる

## なぜ要るか

運営（げんきさん）が手を動かさないと、そこで止まってしまう所がある。

| 申込 | 止まると何が起きるか |
| --- | --- |
| 参加申込 | **許可を出すまで、その人の教材が開かない** |
| 受講コードの申込 | 請求書を送るまで、受講コードが出ない |
| 修了証の発行申請 | 候補日を出すまで、討議の日が決まらない |
| 実務トレーニングの申込 | 請求書を送るまで、第2章から先が開かない |
| 事業者の登録 | （止まりはしないが、使い始めたことを知りたい） |

**どれも、待っている人は何もできない。**運営が画面を開くまで気づかない作りだと、
現場に出ている日に丸一日止まる。

メールではなく LINE にしたのは、**現場で見るのが LINE だから**。

## 使う仕組み

**LINE Notify は 2025年3月31日に終わった。** いまは LINE 公式アカウントの
**Messaging API** から push で送る。

- LINE 公式アカウントは無料で作れる
- 送信は**月200通ほどまで無料**。それを超えると有料
- 受け取る人は、その公式アカウントを**友だち追加している**必要がある

いまの使い方（運営1人に、申込のたび1通）なら、200通で当分足りる。
外販が進んで足りなくなったら、まとめて1日1回にするか、有料にする。

## 決めたこと

### 誰が申し込んだかは書かない

本文は「参加申込が1件」と、開く場所だけ。**氏名も会社名も送らない。**

- LINE はよその会社の仕組み。氏名を流せば第三者提供になり、
  個人情報の取扱い（/legal/privacy）に LINE を書き足す話になる。
  **書かなければ、その話が起きない**
- 通知はスマホのロック画面に出る。**人の名前がそこに出る。**
  現場で画面を見られることもある
- 知らせの役目は「忘れないこと」。誰かはアプリを開けば1タップで分かる

本文を作る所（`src/lib/notifyText.ts`）は、種類・住所・件数の3つしか
受け取らない。**受け口を増やさないこと。** 増えれば、そのうち誰かが名前を入れる。
`npm run test:notify` が見ている。

### 送れなくても、申込は通す

LINE が落ちていたら申し込めない、では本末転倒。
失敗は握りつぶして先へ進める（`notify` は例外を投げない）。
待ち時間は3秒で諦める。

### 鍵に NEXT_PUBLIC_ を付けない

付けると画面に埋まって、**誰でも運営のアカウントから送れる**ようになる。

## 用意する手順

### 1. LINE 公式アカウントを作る

[LINE Developers](https://developers.line.biz/) でログイン（LINEのアカウントで入れる）。

1. プロバイダーを作る（会社名でよい）
2. **Messaging API チャネル**を作る
3. チャネル名は受け取る側に見えるので、**「足場屋革命」**にしておく

### 2. チャネルアクセストークンを取る

チャネルの **Messaging API 設定** の下のほうにある
**「チャネルアクセストークン（長期）」**を発行する。

**この鍵はチャットに貼らないこと。** Vercel の画面に直接入れる。

### 3. 自分の userId を調べる

push は「誰に送るか」を userId で指定する。@ から始まる LINE ID とは別物。

チャネルの **Messaging API 設定** の下に **「あなたのユーザーID」**が出ている
（`U` から始まる長い文字列）。それを使う。

**先に、そのチャネルの QR コードから自分を友だち追加しておくこと。**
友だちでない相手には送れない。

### 4. Vercel の環境変数に入れる

```
LINE_TOKEN = チャネルアクセストークン（長期）
LINE_TO    = 自分の userId（U から始まる）
```

どちらも **NEXT_PUBLIC_ を付けない。** 入れたら再デプロイする。

### 5. 確かめる

`/setup` の「申込の知らせ（LINE_TOKEN / LINE_TO）」が **設定済み**になる。

そのあと、捨てアカウントで参加申込を1件出してみる。
LINE に「【足場屋革命】参加申込が1件」と届けば通っている。

## いま知らせている所

| 種類 | どこから | 開く場所 |
| --- | --- | --- |
| `member` | `/api/member`（参加申込） | `/admin` |
| `order` | `/api/order`（受講コードの申込） | `/owner` |
| `cert` | `/api/issue`（修了証の発行申請） | `/owner` |
| `train` | `/api/train-order`（実務トレーニングの申込） | `/owner` |
| `company` | `/api/admin/setup`（事業者の登録） | `/owner` |

**運営が手を動かさないと先へ進まない所は、全部ここに入れること。**
1つでも抜けると、そこだけ気づけない。`npm run test:notify` が数を見ている。

## これから困ること

**参加申込は、本当はその会社の担当者に届くべき。**

いまは運営（げんきさん）に届く。会社が1つで、その担当者も運営本人なので
それで足りている。よその会社が使い始めたら、**その会社の参加申込が
げんきさんの LINE に鳴る**ことになる。

そのときは、参加申込だけ「その会社の担当者へメール」に移す。
LINE は運営本人の物なので、よその会社の担当者には渡せない。
