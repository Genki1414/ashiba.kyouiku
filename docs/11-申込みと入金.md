# 申込み・受講コード・入金

売り物にするための仕組みです。ここまでは誰でも登録して、事業者を作って、
全部使えていました。

---

## 1. 3つのコードと2つの立場

| | 何のため |
|---|---|
| **受講コード**（12文字） | 1人1枚の**席**。売り物。修了証を出すのに要る |
| **参加コード**（8文字） | 名簿に入るだけ。席は付かない（担当者や、見学だけの人） |
| 証明番号（`AT-西暦月-通し番号`） | 修了証の番号。照会に使う |

| | 誰 | 画面 |
|---|---|---|
| **運営** | 東北三上機材（売る側） | `/owner` |
| **教育担当者** | 買った会社の担当者 | `/admin` `/order` |
| 受講者 | 作業員 | `/join` ほか |

受講者が入れるコードは**入り口が1つ**です（`/join`）。
12文字なら受講コード、8文字なら参加コードとして扱います。
現場の人に2種類を説明しなくて済むように、桁で見分けています。

---

## 2. 買う側の流れ

1. 担当者が `/admin` →「受講コードを申し込む」（`/order`）
2. **人数**を決める。金額が出る（単価×人数＋消費税）
3. 支払い方法を選ぶ
   - **カードで払う** … Stripe の支払い画面へ。払い終わると自動で入金済みになる
   - **請求書で払う** … その場で受講コードが出る。請求書は運営から送る
4. 受講コードを作業員に配る（下の「コードの渡し方」）
5. 作業員は登録 → `/join` でコードを入れる → 学科を受ける

### コードの渡し方

`/order` の上のほうに **受講コードの一覧** が出ます。枚数ではなく、
**コードの文字そのもの**です。ここが無いと、買っても配れません。

- 未使用のものが先に出ます（次に配るのはそれなので）
- `ABCD-2345-6789` のように4桁ずつ区切って出ます。紙に書き写すため
- 読み違えやすい `0` `1` `O` `I` `L` は使っていません
- 「写す」で1件、「まとめて写す」で未使用ぶんを全部、コピーできます
- 使ったコードは、**使った人の氏名と日にち**が付いて、下に回ります
- 20件を超えると畳まれます（「残り○件も出す」で全部出ます）

1つのコードは1人しか使えません。期限は既定で発行から1年です。

> **請求書払いでも、受講は入金前から始められます。**
> 止まるのは**修了証**だけです（労働安全衛生法の教育そのものは受けられるが、
> 資格を証する紙は入金確認まで出さない、という切り分け）。

---

## 3. 売る側（運営）

`/owner` で全事業者の注文が見られます。

- **入金待ち** が上に出ます。請求書の入金を確認したら「入金を確認した」
- カード払いの入金は Stripe からの知らせで自動的に立ちます（手で押せません）
- 入金前の注文は「取り消す」ができます。入金済みは取り消せません（返金は Stripe 側で）
- **無償利用**：受講コードが無くても修了証を出せる事業者。試用や社内利用のときだけ

誰が運営かは Vercel の環境変数 **`OWNER_EMAILS`**（コンマ区切り）で決めます。
**ログインしているメールと、ここに入れた住所が一字でも違うと開けません。**
`/setup` の「ログイン」に「いまのメール」と「運営として認めるか」が出るので、
そこで見比べてください。
データベースには持たせていません。担当者の画面から自分を運営に昇格させる道を
作らないためです。

---

## 3.5 誰が教材を開けるか

**受講コードを引き換えた人だけ**が、学科（`/edu`）と実務トレーニング（`/training`）を
開けます。登録しただけの人が開くと「受講コードを入れてください」で止まります。

通すのは次の2つだけです。

| 条件 | どういう人か |
| --- | --- |
| `seats.used_by` が自分 | 受講コードを引き換えた人 |
| 所属事業者が **無償利用** | 試用・社内利用。運営が `/owner` で立てる |

**教育担当者だからといって通しません。** 登録すれば誰でも自分の事業者を作って
担当者になれるので、担当者を通すと「登録すればタダで見られる」のと同じになります。
下見をさせたい相手には、運営が `/owner` で**無償利用**を立ててください。

参加コード（8文字）は名簿に入るだけのものです。これでは受講できません。

見張りは `src/lib/entitleQuery.ts`（決まり）と `src/app/edu/layout.tsx` ／
`src/app/training/layout.tsx`（入口）にあります。画面を隠すのではなく、
サーバでここを通してから中身を作ります。作ってしまうと、
教材の文章がそのまま返ってしまうからです。単元の頁は作り置き（静的生成）しません。

無償利用で開いているときは、画面の上に「無償利用の事業者として開いています」と出ます。
黙って開けていると、コードの要る仕組みが効いていないように見えるためです。

## 4. 修了証を出せる条件

学科の条件（全13単元＋修了試験の合格）に加えて、

| 受講の状態 | 修了証 |
|---|---|
| 受講コードがあり、その注文が**入金済み** | 出せる |
| 受講コードがあるが**入金前** | 出せない（「未入金の注文です」） |
| 受講コードが無く、事業者が**無償利用** | 出せる |
| 受講コードが無く、無償利用でもない | 出せない（「受講コードがありません」） |

この判定は**データベースのトリガ**（0009）で止めています。
画面やAPIを通さずに行を入れようとしても止まります。

## 5. 設定するもの（Vercel の環境変数）

| 名前 | 中身 | 無いとどうなるか |
|---|---|---|
| `OWNER_EMAILS` | 運営のメール（コンマ区切り） | `/owner` を誰も開けない |
| `SEAT_UNIT_PRICE` | 1人あたりの単価（税抜・円） | 仮の 3,000円 になる |
| `STRIPE_SECRET_KEY` | Stripe の秘密鍵（`sk_`） | カード払いが画面に出ない（請求書払いだけ） |
| `STRIPE_WEBHOOK_SECRET` | Stripe の署名の鍵（`whsec_`） | カードの入金が自動で立たない |
| `SITE_URL` | 本番のURL | 支払い後の戻り先が、配信ごとに変わる住所になる |

**`STRIPE_SECRET_KEY` に `NEXT_PUBLIC_` を付けないこと。** ブラウザに鍵が出ます。

### Vercel の Type（Secret か Config か）

`NEXT_PUBLIC_` が付いた変数は**ブラウザに埋め込まれる前提**のものです。
Vercel で **Secret** にすると組み立てのときに読めず、アプリに届きません。**Config** にしてください。

| 変数 | Type |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` / `NEXT_PUBLIC_AUDIO_BASE` | Config |
| `SELLER_*` / `SEAT_UNIT_PRICE` | Config（公開する情報） |
| `OWNER_EMAILS` / `EXAM_SECRET` / `SITE_URL` | Secret（Config でも可） |
| `SUPABASE_SERVICE_ROLE_KEY` / `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` | Secret |

`SEAT_UNIT_PRICE` は `NEXT_PUBLIC_` を付けません。
単価はサーバだけが読み、画面には `/api/order` から渡します。
画面で読むと、見せる金額と請求する金額が食い違うためです
（`tests/env-usage.mts` が見張っています）。

### Stripe の webhook

Stripe のダッシュボードで、送り先に
`https://（本番のURL）/api/stripe/webhook` を登録し、
イベントは **`checkout.session.completed`** だけで足ります。
表示された署名の鍵（`whsec_...`）を `STRIPE_WEBHOOK_SECRET` に入れてください。

## 6. まだ決めていないこと

- **特定商取引法に基づく表記**。ネットで売るなら要ります（事業者名・住所・連絡先・
  価格・支払方法・引渡し時期・返品）。まだ作っていません
- **利用規約・個人情報の扱い**。同じく、売る前に要ります
- **返金**。いまは Stripe 側で操作する前提です。画面からはできません
- **席の期限**。既定で1年です。この年数でよいか
