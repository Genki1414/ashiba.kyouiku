## ① 月別（全体・クーポンごと・支払先ごと）

広告費は**月ぎめで払う。**「今月いくら振り込むのか」が1つの数字で要る。
これまでは、始めてからの通算しか出ていなかった。

3か所に畳んで置いた。

| どこ | 何のため |
| --- | --- |
| 全体 | その月に、広告費がいくら出たか |
| 支払先ごと | **その先に、その月いくら払うか**（請求のもと） |
| クーポン1枚ごと | どのクーポンが、いつ効いたか |

畳んである。開くのは、月を締めるときだけ。

### 月の切れ目は、日本の時計で決める

使った日は、データベースには**世界標準時**でしまってある。
そのまま月で切ると、こうなる。

```
10月1日 0時30分（日本）＝ 9月30日 15時30分（世界標準時）
                          → 9月に入ってしまう
```

1件でも落ちれば、払う額が変わる。`monthKeyJst()` で日本の日付に直して
から切る。境目は tests/coupon.ts が見ている（月初の未明・月末の夜・年またぎ）。

### 数えるのは1か所だけ

サーバ（`/api/owner/coupons`）で数えて、画面はそれを並べるだけ。
画面で足し直すと、**同じ月なのに場所によって違う額**が出る。

並びも1つの部品（`Months`）にした。3か所で同じ形。
別々に書くと、片方だけ列が増えて読み比べられない。

**入金済みと入金待ちは、行を分けたまま。**足した額は、どこにも出さない。
足すと払い過ぎになる。

## ② コードのコピー

クーポンのコードは、LINE や電話で相手に伝えるもの。
打ち直すと `O` と `0`、`I` と `1` で必ず間違える。

`CopyBtn`（新）を1つ置いた。ホーム画面のアプリに入るコードにも
同じものがあったので、そちらと同じ作りに揃えてある。

写せない相手（古いブラウザ・安全でない接続）には、**黙って失敗させない。**
「長押しで選んでください」と出す。

## ③ 配るためのクーポン画像

紹介してくれる団体さんに、LINE やメールでそのまま渡せる絵を作る。

1200 × 630。貼ったときに切られない形。
描くのはブラウザの中だけで、**サーバは通さない**（置いておく必要が無い）。

載せるもの　　… 店の名前・値引き・クーポン名・コード・期限・入れる場所
載せないもの　… **広告費の率と支払先**（こちらの取り分。相手が読む）

期限が無いときも「期限なし」と書く。空欄だと「切れているのでは」と

## その日のうちに直したこと（2026-09-10）

げんきさん「月別が見れない、表示がない」「広告費の入金済みとはどういう意味？」

### 0件のとき、枠ごと消していた

`if (!months.length) return null` にしていた。
まだ誰もクーポンを使っていないので、**3か所とも丸ごと消えていた。**
作ったのに無いように見える。

空だと書いてある枠を出すことにした。開くと
「このクーポンが使われると、月ごとの件数・売上・広告費がここに並びます」。

出す・出さないを、こちらの都合（データが有るか）で決めない。
探させるくらいなら、空だと書く。

### 「入金済み」が二通りに読めた

```
広告費（入金済み）   20,250円
```

**こちらが払い終えた広告費**、と読める。そうではなかった。
正しくは「お客様からご入金があった申込みの分の、これから払う広告費」。

言葉を分けた。

| 前 | いま |
| --- | --- |
| 広告費（入金済み） | お支払いする広告費 |
| 売上（税抜・入金済み） | 売上（税抜） |
| 入金済み 5件 | お客様の入金あり 5件 |
| 入金済み（明細の行） | 入金あり |

そのうえで、上に3行で書いた。

```
上の金額は、お客様からのご入金を確認した申込みの分です。
取り消された申込みは含みません。
まだご入金がない分は、売上 ◯円／広告費 ◯円 で、上の数字には入っていません。
「お支払いする広告費」は、これからお支払いする額です。
振込が済んだかどうかは、この画面では見ていません。
```

最後の1行が大事。**広告費を振り込んだかどうかは、この仕組みでは持っていない。**
持っていないものを、持っているように見せない。

見張りで「入金済み」という字が画面に出ないようにした（誰の入金か分からないため）。

## 編集と削除（0038・2026-09-10）

げんきさん「クーポンに編集と削除を追加して」。

### 先に塞いだこと：請求書がクーポンの名前を生で読んでいた

請求書は「値引き（◯◯協会 会員割）」と出す。その名前を、
**そのつど `coupons.name` から読んでいた。**

つまり、名前を直すと**もう渡した請求書の字まで変わる。**
請求書は相手の手元にある書類で、こちらの都合で書き換わってはいけない。
税務調査で出したものと、いま画面に出るものが違う、が起きる。

だから、使われた時の名前を記録に焼き付けた（`coupon_uses.coupon_name`）。
使った時の率（`reward_rate`）を焼き付けてあるのと、同じ考え方。

| | どこ | 動くか |
| --- | --- | --- |
| 使った時の名前 | coupon_uses.coupon_name | 動かない。請求書はこれを見る |
| いまの名前 | coupons.name | 直せる。これから使う人が見る |

これまでの記録には、いまの名前を入れておいた（名前は変えられなかったので、
いまの名前＝使った時の名前）。焼き付けが無い古い記録だけ、
請求書はいまの名前で埋める。**ここで空にすると、古い請求書から
値引きの名前が消える。**

### 直せるものを、2つに分けた

| | 直せるもの |
| --- | --- |
| いつでも | 名前・期限・使える回数・支払い先・広告費の率 |
| 使われる前だけ | クーポンの文字（コード）・値引きの形と額 |

コードと値引きは、**配った絵と紙に刷ってある。**
使われたあとに変えると、相手の持っている券が通らなくなるか、
書いてある額と違う額が引かれる。

使われたら欄ごと出さずに、なぜ直せないかをその場に書く。
画面で隠すだけでなく、口（`/api/owner/coupons`）でも断る。
**見た目だけで守らない。**

広告費の率を直しても、すでに使われた分の額は動かない
（使った時の率が記録に残っている）。画面にもそう書いた。

### 消せるのは、一度も使われていないクーポンだけ

使われたものを消すと、**払った広告費の裏が取れなくなる。**
表の作りでも押さえてある（`coupon_uses` が `on delete restrict`）。

押せてしまうと「押したのに断られた」になるので、
使われたクーポンには削除の札を出さない。
代わりに「使われたクーポンは削除できません（停止はできます）」と書く。

数えられなかったときは、**0件として扱わない。**
0と思い込むと、使われたクーポンを消してしまう。
