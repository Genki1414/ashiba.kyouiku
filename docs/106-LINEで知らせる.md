## 1　本人のLINEに知らせが届く

### なぜ

受講コードを配っても、修了証を出しても、**相手が開くまで伝わらない。**
ホームの「お知らせ」は、開いた人にしか届かない。開くのをやめた人には永久に
届かない。現場の方はメールを見ないが、LINE は見る。

### どう作ったか

**新しい呼び出しを足していない。**返事を残す所（`addNotice`）は1本しかないので、
そこに送る所をぶら下げた。これで、いまある10種類の知らせが全部 LINE に乗る。

| 種類 | LINE に出る見出し |
| --- | --- |
| `given` | 受講コードが届きました |
| `seat` | 受講コードが出ました |
| `cert` | 修了証が出ました |
| `member_ok` / `member_ng` | 会社とつながりました／参加申込が断られました |
| `train` | 実務トレーニングが開きました |
| `slot` / `room` / `pass` / `issue_ng` | 討議・実技まわり |

文面は画面のお知らせと同じ言い方（`DEFS` を使い回す）。片方だけ直すと、
LINE に古い言い方が残る。

### 決めたこと

- **残せてから送る。**先に送ると、残せなかったときに「知らせは来たのに
  画面に無い」という、いちばん困る出方をする
- **本部が書いた一言（note）は送らない。**断った理由には氏名や会社名が
  入りうる。LINE はよその会社の仕組みなので、人の名前を流さない
  （`src/lib/notifyText.ts` と同じ考え）。理由は開いた先の画面に出る
- **送れなくても、元の操作は通す。**LINE が落ちていたら受講コードが配れない、
  では本末転倒。3秒で諦める
- LINE を結んでいない人（メールで登録した人）には、何も起きない

### 送るアカウント

その店の公式アカウント（`LINE_MENU_TOKEN`）。リッチメニューを配ったのと同じ鍵。

LINE の利用者番号は**プロバイダーごと**に決まる。ログインチャネルと公式
アカウントを同じプロバイダーに置いてあるので、ログインでもらった番号を
そのまま送り先に使える。**分けて作ると番号が合わず、届かない。**

## 2　LINEに「設定」と送ると、様子が返る

運営が現場に出ているあいだ、パソコンを開かずに設定を見たい。

合言葉は **セットアップ／設定／setup**（前後の空白・大文字小文字は問わない）。
**ちょうどその字のときだけ。**「設定を変えたいのですが」は拾わない。
ふつうの相談に機械の返事をかぶせないため。

返ってくるもの（`src/lib/opsStatus.server.ts`）

```
【特別教育ドットコム】設定の様子

データベース　0033（要 0033）
Supabase　OK
運営　1人
申込の知らせ　OK
LINEログイン　OK
LINEで送る　OK
LINEで受ける　OK
0円のまま公開　なし

https://www.tokubetsu-kyouiku.com/setup
```

### 決めたこと

- **署名を必ず確かめる。**確かめないと、この住所を知った人が偽の
  「運営からの指示」を投げ込める。鍵（`LINE_BOT_SECRET`）が入っていなければ
  何も受け付けない
- **運営にしか返さない。**ほかの人が同じ字を送っても黙っている。
  返すと、公式アカウントの応答メッセージや手動チャットと二重になるし、
  設定の様子はよそに見せるものではない
- 運営かどうかは **LINEの番号 → 利用者 → メール → OWNER_EMAILS** の順。
  LINE の表示名では見ない（名前は誰でも真似できる）
- **偽物には 200 を返さない**（401）。「届いた」と教えない。
  それ以外は必ず 200（LINE は 200 以外だと何度も送り直してくる）
- 鍵の値も、値段の上書きも本文に入れない。**トークは残る**ので、
  商売の中身は画面の側に置く
- 友だち追加（follow）には何もしない。あいさつは公式アカウントマネージャーの
  あいさつメッセージで出す（docs/105）

## 2-1　ログインの見張りが、LINE の出入り口を塞いでいた

げんきさん（2026-09-09）「検証でエラー出る」。

`src/middleware.ts` は、ログインのクッキーが無い相手の `/api/…` を
その場で 401 にする。**LINE はログインを持っていない。**
だから LINE Developers の「検証」は、こちらの入口に届く前に弾かれていた。

同じ理由で **`/api/line/login` も塞がっていた。**こちらはもっと悪い。
「LINEではじめる」を押す人は、**まだログインしていない人しかいない。**
つまり LINE ログインは、押した全員が弾かれていた。

Stripe の入金の知らせ（`/api/stripe/webhook`）と同じ扱いにして、
`/api/line` をログインの手前で通す。**代わりに署名で守る。**

手元で確かめた（ログインの見張りを効かせた状態で）。

| 道 | 返り |
| --- | --- |
| `/api/me`（比較用） | 401「ログインが要ります」 |
| `/api/line/webhook`（正しい署名） | 200 `{"ok":true}` |
| `/api/line/webhook`（署名なし・よその鍵） | 401 |
| `/api/line/login` | 307（LINE の認可画面へ） |

見張りは `tests/auth-gate.ts`（開けすぎていないかも見る）。

## 3　パスワードを忘れたとき

LINE で入った人には、**そもそもパスワードが無い。**メールも持っていない
（`line-<番号>@line.invalid` という届かない住所を当ててある）。

前は「パスワードを忘れた」の画面で LINE の入口を隠していたので、
**そこで行き止まりになっていた。**いまは出す。押せばそのまま入れる。

| 入り方 | 忘れたとき |
| --- | --- |
| メールとパスワード | これまでどおり、決め直しのリンクをメールで受け取る |
| LINE | パスワードは無い。「LINEではじめる」を押すだけ |

LINE のアカウントごと失った人は、こちらでは戻せない。会社の教育担当者から
受講コードを配り直す（受講の記録は残っているので、修了証は消えない）。

## 4　仮のメールを画面に出さない

`line-U4af…@line.invalid` が名簿・マイページ・帳簿にそのまま並んでいた。
担当者は「これは何かの間違いか」と思って本人に聞き直すことになる。

**「LINEで登録（メールなし）」と出す**（`emailLabel`）。
持っていないことが分かる字にする。

この関数は画面からも読むので、鍵を読む `line.ts` とは分けて
`src/lib/lineEmail.ts` に置いた（`tests/env-usage.mts` が見張っている）。
