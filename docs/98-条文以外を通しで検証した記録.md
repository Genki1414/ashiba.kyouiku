## 2　見つけたもの

### 2-1　特別教育ドットコムで合言葉を決め直すと、足場屋革命に着いていた

いちばん重い。

合言葉の決め直しは、メールのリンクで戻ってくる。その戻り先は
`src/lib/siteUrl.ts` に**足場屋革命の住所が1本だけ**決め打ちしてあった。

    export const FALLBACK_SITE = "https://kyouiku.ashibase.jp";

特別教育ドットコムにはまだ `NEXT_PUBLIC_SITE_URL` を入れていない。
だから**あの店で登録した塗装屋さんが、合言葉を決め直すと足場屋革命に着く。**
LINE の知らせのリンクも同じ所を読む（`src/lib/notify.server.ts`）。

店が1つだったときは正しい作りだった。**店を増やしたときに、
ここを見落とした。**

#### 直したもの

住所を店ごとに持たせた（`src/content/brand.ts` の `site`）。

    ashibaya   "https://kyouiku.ashibase.jp"
    tokubetsu  ""   ← まだドメインを当てていない

空のときは「いま開いている住所」へ戻す。**よその店の住所は借りない。**
配信ごとに変わる住所なので Supabase の許した住所に無ければ弾かれるが、
**弾かれる方が、別の店に着くよりよい。**

`/setup` に「この店の住所」の行を足した。決まっていなければ橙で出る。

### 2-2　画面は404にしたのに、口が開いていた

きのう（docs/97）`/training` と `/train` を404にした。ところが

    /api/train-order   ← **注文を立てる口**
    /api/training
    /api/training/view

は開いたままだった。**扉を閉めて、窓を開けていた。**
とくに `/api/train-order` は請求書の出る注文を作る口で、
あの店の利用規約が対象にしていない売り物の注文が、本当に立つ。

3本とも、売っていない店では 404 を返すようにした。

### 2-3　売っていないものが、まだ3か所に出ていた

| 所 | 何が出ていたか |
| --- | --- |
| ホームの「受講コードを入れる」札 | 「実務トレーニングの第1章は、コードが無くても遊べます」 |
| 教育担当者の名簿（`LearnerCard`） | 実務トレーニングの成績の札。押しても「まだ」だけ |
| マイページの「端末に残るもの」 | 「実務の成績が消えます」 |

3つ目は、**あの店の個人情報の取扱い（第7条）と食い違っていた。**
きのう規約から実務トレーニングを外したので、画面だけが残っていた。

名簿の札は数を決め打ち（`grid-cols-3`）にしていたので、
1枚減らすと1枠空く。札の数で並べるように直した。

### 2-4　`/api/health` が誰でも見られて、値段の上書き表が公開だった

`/api/health` は鍵を返さないので、**わざとログイン無しで開ける**作りにしてある
（げんきさんが、壊れているときに開いて見るため）。それは変えない。

ただし返している中に

    priceOverrides  「コードでは4,500円だが、いま6,000円で売っている」の表

があった。誰でも読めると、買う人に**値引きの余地があるように読まれる。**
ここだけ運営に限った。単価そのもの（`prices`）は特商法の表記に載せている
値なので、そのまま誰でも見られる。

`/setup` は「運営でログインすると出ます」と出す。
**null（出していない）と空配列（上書きなし）を混ぜない。**
混ぜると、ログインせずに開いた人に「上書きなし」と出て、
本当は上書きされているのに安心してしまう。

### 2-5　特別教育ドットコムからは、更新のお知らせに二度と辿り着けなかった

`/updates`（更新の一覧）への札は、**実務トレーニングの画面の中にしか無かった。**
あの店では `/training` ごと 404 なので、
**お知らせを一度閉じたら、それきり読めない。**

3-1 で作った「押せる所を全部たどる試験」で、あの店の行き先に
`/updates` が1つも現れなかったことから見つけた。

どちらの店にもあるホームの足元（特商法・利用規約・個人情報の隣）に置いた。
足場屋革命でも、今までゲームの画面の中に埋まっていたので、見つけやすくなる。

## 3　同じ見落としを二度としないために

### 3-1　押せる所を全部たどる試験を足した（`tests/e2e-links.mjs`）

今回の「行き先の無い札」は、**足場屋革命では正しく開く。**
あちらの試験では絶対に出ない。1画面ずつの試験でも出ない。

ログインしていない人が着ける画面を回り、`<details>` を開いて、
出ている `a[href]` を全部集めて、1つずつ開く。
404 になったら**どの画面のどの札から来たか**まで出す。

### 3-2　`tests/brand.ts`（462件）に足したもの

- 店ごとに住所を持っているか。**同じ住所を2つの店が持っていないか**
- 住所を1つ決め打ちで書き戻していないか
- 住所が決まっていない店で、いま開いている住所へ戻すか
- 売っていないものの**口**（API）が、handler の数だけ閉じているか
- 担当者の名簿・マイページの書き方を店で分けているか
- リクエストの入口は店で分けないこと（ここは今までどおり）

### 3-3　実務トレーニングの試験を、店に合わせた

`e2e-ch1` `e2e-ch1-sk` `e2e-ch2` `e2e-ch3` `e2e-demo23` `e2e-catalog-demo`
`e2e-record` `e2e-resume` `e2e-scene-fit` `e2e-sfx` `e2e-tap` の11本は、
実務トレーニングそのものの試験なので、売っていない店では走れない。

**素通りさせない。**売っていない店では、画面（/training・/training/ch1・
/training/catalog・/training/demo・/train）と口（/api/training・
/api/training/view・/api/train-order）が**全部 404 であることを確かめて**
終わる。共通の仕組みは `tests/training-store.mjs`。

どちらの店かは、環境変数ではなく**実際の返事**で見分ける。
店の名前を試験に持ち込むより確か（名前を足しても、閉じ忘れていれば通ってしまう）。

`e2e-update-notice` は実務トレーニングの試験ではないので、
**どちらの店にもある画面（ホーム）で見る**ように直した。
`e2e-order` と `e2e-admin` が、ホームの描き終わりを
「実務トレーニング」という**売り物の名前**で待っていたのも直した。
売り物の名前で待つと、店を増やすたび関係のない試験が止まる。

### 3-4　お知らせの覆いで、時々落ちる試験があった

`e2e-cert` が「出せない理由が出る」で時間切れになるのに、
**そのすぐ次の行では、その理由の文字が読めていた。**

更新のお知らせは画面が描かれたあとに出てくるので、
閉じ損ねると、そのあとの札に覆いかぶさる。要素は在るのに
「見えていない」ので、待ち受けだけが時間切れになる。

**お知らせを足した日にだけ落ちる**ので、気づきにくい。
居なくなるまで何度か閉じるようにした。

- 単価そのものは誰でも見てよいか

   とくに「値段を環境変数で上書きしていないか」。

   `src/content/brand.ts` の `TOKUBETSU.site` ／ Vercel の2つ ／
   Supabase の許した戻り先。
3. 受講リクエストの釦（docs/97）は、本物のログインが要るので
   こちらでは押せていない。3通り見てもらう。
