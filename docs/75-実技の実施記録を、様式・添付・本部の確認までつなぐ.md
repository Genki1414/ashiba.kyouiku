## 1. 何が問題だったか

実技のある特別教育は **38講座**（受講できる45講座のうち）。
学科をうちで受けたあと、**実技は事業者が自社で行う。**

**うちが見ていたのは、発行申請に入れてもらう2つだけだった。**

- 実技を行った日
- 実技を行った人の名前

**これは、実技をやったことの証明になっていない。**
日付と名前は、打ち込めば通ってしまう。
学科だけ受けて、実技をやらずに修了証が出る道が空いていた。

---

## 2. 決めたこと

1. 実技の手引きに、**実施記録の様式**を付ける。**ダウンロードして印刷して使う**
2. 様式に入れるもの
   - **実施内容**（システム側で講座ごとに書いておく。**チェックできる**）
   - **参加者名**
   - **実施事業者名**
   - **実施事業者印**
3. **発行申請のときに、書いた記録をアップロードする**
4. **本部が中身を確認してから、修了証を発行できる**

---

## 3. 様式（`src/lib/drillRecord.ts`）

**紙は1か所でしか組み立てていない。**
同じ紙が「手引きの画面」と「ダウンロード」の2か所に出るので、
**2か所に書けば、必ず片方だけ直す日が来る。**

中身は4つの節。

| 節 | 何 |
|---|---|
| 1. 実施したこと | **講座ごとの記入欄**（`DrillGuide.form`）。機械の種類、点検、合図など |
| 2. 実施事業者 | **実施事業者名／所在地／実施責任者／実技を行った人／実施事業者印** |
| 3. 参加者 | **12行。**氏名・生年月日・署名（同姓の人がいる会社で分からなくならないよう、生年月日も） |
| 4. 実施内容 | **段ごとに、実施内容をチェック欄付きで並べる** |

### 実施内容のチェック欄は、どこから来るか

**手引きの箇条書きのうち、上の階層の行**（全角空白で始まらない行）を拾っている。
ぶら下がりの細かい行まで並べると、紙が読めなくなるため。

**38講座ぶん、新しく書き起こさずに済んでいる。**
手引きの中身はもともと講座ごとに書いてあるので、それがそのまま実施内容になる。
移動式クレーンなら36項目、いちばん多い特殊化学設備で56項目。

**チェック欄の数と、実施内容の数が合っているか**は毎回テストで見ている。

### ダウンロード

`/api/drill-record?courseId=…` が、そのまま印刷できる1枚もの（HTML）を
**添付として**返す。ログインは要らない（実技をやるのは会社の人で、
うちのアカウントを持っていない）。

開けば「印刷する」のボタンが出る。**ブラウザの印刷からPDFにもできる。**

**PDFで返していない。**PDFを作る道具を入れていないため。
入れるほどの値打ちがあるかは、使ってみてから決める。

## 4. 添付（`src/lib/shrink.ts` と `/api/issue`）

**実技の講座は、実施記録を添えないと申請できない。**

| 決め | 値 |
|---|---|
| 受ける形 | JPEG・PNG・WebP・PDF |
| 件数 | **3件まで** |
| 1件 | **5MB まで** |
| 合計 | **10MB まで** |

**写真は端末の中で縮めてから送る。**長辺2000ピクセル・JPEG。
現場で撮った写真はそのままだと3〜8MBあるが、**A4に書いた字が読めればよい**ので、
これで1件400KB前後になる。縮められない形のときは、縮めずに送って、大きさで弾く。
**黙って壊すよりはよい。**

**端末の言い分は信じない。**サーバ側でも、data URL の頭・件数・大きさを見ている。

### 置き場所

**Supabase Storage は使っていない。**データベースの表（`cert_request_files`）に、
data URL のまま入れている。

理由は、**記録の寿命が受講の記録と同じ**だから。
3年保存して、そのあと消す。同じ場所に置けば、同じ消し方に乗る。
（申請が消えれば記録も消える。3年たった人を消すときも一緒に消える）

## 5. 本部の確認

- 一覧には**「何が付いているか」だけ**が来る（写真の中身は来ない）。
  200件ぶんの写真を一覧に載せると、開くだけで何十MBになる
- 押した1件だけを `/api/owner/issue/file?id=…` が返す。**本部だけ。キャッシュしない**
- **記録が付いていない実技の申請は、「修了にする」を押せない**
- ボタンの字も「**記録を確かめた。修了にする**」に変えた

## 6. データベースで止める（ここがいちばん大事）

**画面の作りだけで縛ると、画面を変えた日に抜ける。**だから 0027 で止めている。

| 決まり | どこで |
|---|---|
| 実技の申請に、記録が1件も無ければ**断る** | `request_cert` |
| 4件以上は**断る** | `request_cert` |
| 大きすぎるものは**断る** | `request_cert` |
| 出し直したら、**前に添えた記録は消して入れ替える** | `request_cert` |
| 実技の申請は、記録が無ければ**通せない** | `clear_request` |
| 申請が消えれば、記録も消える | `on delete cascade` |
| 3年たった人を消すとき、記録も消える | `erase_learner` |
| 見られるのは本人と、同じ事業者の担当者だけ | RLS |
| クライアントから直に書けない | insert のポリシーを置かない |

### 危なかったところ

**`create or replace` は、引数が違えば別の関数になる。**
`request_cert` に `p_files` を足しただけだと、
**記録を見ない8引数の古いほうが残ったまま**になっていた。
名前で呼ぶ（PostgREST の rpc）と、どちらに当たるか分からない。
**先に `drop function` してから作り直している。**

## 7. 見張り

**`supabase/tests/drill.sql`（37件）**。実技のある講座なら、どれでも当てられる。

- ⑤ 出し直したら、記録が1件に入れ替わる／入れ替わったのは新しいほう
- ⑫ 記録なしでは申請できない
- ⑬ 4件は多すぎる
- ⑭ 記録が無ければ通せない／止まったので、まだ open
- ⑮ 受講を消すと記録も消える／ほかの人の記録は残っている／RLS が入っている

**`tests/cert.ts`（638件）**。38講座ぜんぶに当たる。

- 様式に「実施内容」「参加者」「実施事業者名」「実施事業者印」がある
- **チェック欄の数＝実施内容の数**
- 強調の印（`**`）が、そのまま紙に刷られていない
- 手引きの法定時間が、講座の実技の時間と合っている
- **学科だけの講座に様式が無い**
- 様式は1か所で組み立てている（画面もダウンロードも同じものを使っている）
- 申請で記録を確かめている／上限が決まっている
- 0027 が、記録なしの申請を断る／記録なしでは通させない／古い関数を落としている
- 本部だけが記録を開ける／キャッシュしない

**`tests/e2e-issue.mjs`（512件）**。実物の画面で。

- 様式をダウンロードできる（添付・講座ごとのファイル名・中身）
- 学科だけの講座に様式は無い（404）
- 実施記録を選ぶ口がある／選んだ記録の名前が出る
- **実施記録が申請と一緒に乗る／端末で縮めてから送っている**

## 8. 残していること（正直なところ）

**本部が見るのは、送られてきた紙そのもの。**
うちの側で「実施内容のチェックが埋まっているか」までは見ていない。
写真を機械が読んで判定するところまではやっていない。

**実技をやったかどうかの最後の担保は、事業者の印にある。**
そこは変わっていない。変わったのは、
**「打ち込めば通る」から「書いて、押して、撮って、見せる」になった**こと。

**本番の Supabase に 0027 を流すこと。**（0025・0026 もまだなら、先に）
