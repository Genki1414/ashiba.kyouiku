# 会社と個人の紐付け（在籍）

**登録しただけでは、会社の名簿には並びません。**
人と会社をつなぐ操作が別に要ります。

人は辞めますし、よその会社へ移ります。
それでも **受けた記録は、受けた当時の会社に残らないと困ります**
（特別教育の記録は、教育を行った事業者が3年保存する決まり）。
そのための作りです。

---

## 1. つなぎ方は2つ

### ① 自分でさがして申し込む（許可が要る）

```
受講者：会社名でさがす → 見つけたら「申し込む」
                              ↓
教育担当者：/admin の「参加の申し込み」で［許可する］／［断る］
                              ↓
                        名簿に入る
```

コードを渡されていない人でも、自分から入れます。
よその会社の名簿に勝手に入られないよう、**会社の許可を挟みます**。

### ② コードを入れる（許可は要らない）

- **受講コード（12文字）** … 1人1枚の席。入れた時点で名簿に入る
- **参加コード（8文字）** … 席を使わずに名簿へ入る

コードを渡した時点で会社が認めているので、許可は挟みません。

---

## 2. 外すとき

**どちらからでも外せます。許可は要りません。**
辞めるときに会社の返事は待てないからです。

| 誰が | どこから |
| --- | --- |
| 受講者 | `/join` の「この会社との紐付けを外す（退職）」 |
| 教育担当者 | `/admin` の各人の「退職にする」 |

**外しても記録は消えません。**名簿には「退職」の印が付いて残ります。
担当者の画面では下に並び、「退職した◯人を隠す」で畳めます。

---

## 3. 記録がどこに残るか

受講（`enrollments`）は **「どの会社の席で受けたか」を自分で持っています**
（`enrollments.company_id`）。人が辞めても移っても、この紐付けは動きません。

```
田中さんが A社の受講コードで受講 → 記録は A社のもの
    ↓ 退職して B社へ
A社の名簿   … 田中（退職）として記録が残る
B社の名簿   … 田中は在籍。ただし A社で受けた記録は見えない
```

B社が田中さんに受けさせたければ、B社の受講コードを渡します。
そのぶんの記録は B社のものになります。

---

## 4. 在籍の形（`memberships`）

| 列 | 意味 |
| --- | --- |
| `requested_at` | 申し込んだ日 |
| `approved_at` | 会社が許可した日。**空なら申請中** |
| `left_at` | 抜けた日。退職・転職・断られた |

- **在籍中（許可済み・未退職）は1人1社**
- 同じ会社への開いている申し込みは1件だけ
- よその会社の許可が下りたら、前の在籍は自動で閉じる（転職）

`users.company_id` は「いま在籍している会社」の控えです。
書き換えは `join_company` / `leave_company` / `request_membership` を通します。

---

## 5. 会社さがしについて

`/api/companies?q=…`。**名前だけ**を返します。
参加コードも担当者の名前も返しません。
2文字以上の当たりが要り、20件までです（片っ端から集められないように）。
